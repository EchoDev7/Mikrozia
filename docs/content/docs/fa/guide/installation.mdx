Mikrozia **فقط به‌صورت RouterOS Container** نصب می‌شود. پلتفرم پشتیبانی‌شده
MikroTik RouterOS نسخهٔ `7.25+` همراه با بستهٔ Container دقیقاً هم‌نسخه است؛
CHR x86_64 محیط مرجع این مسیر مبتدی است. Mikrozia روی VPS لینوکسی، با systemd،
از Tarball یا آرشیو انتشار، روی Windows، یا به‌عنوان Stack تولیدی Docker Compose
نصب نمی‌شود.

<Callout type="warn">
  Mikrozia هرگز Rule مربوط به Firewall، NAT، Port Forward، Masquerade، Routing،
  Address List یا Access Control را در RouterOS ایجاد یا تغییر نمی‌دهد. این
  تصمیم‌ها در اختیار مدیر RouterOS است. Mikrozia فقط پورت‌هایی را که داخل
  کانتینر گوش می‌دهد مستند می‌کند.
</Callout>

## پیش‌نیازها

| منبع | حداقل | پیشنهاد |
| ---- | ----: | ------: |
| RouterOS | `7.25.0` Stable | آخرین Stable |
| بستهٔ Container | دقیقاً هم‌نسخه RouterOS | دقیقاً هم‌نسخه RouterOS |
| RAM | 2 GiB | 4 GiB |
| فضای آزاد | 2 GiB | 8 GiB یا بیشتر |
| معماری | `linux/amd64` (CHR) | `amd64`، `arm64/v8`، `arm/v7` منتشرشده |

وضعیت فعلی را پیش از شروع بررسی کنید:

```text
/system/resource/print
/system/package/print
/disk/print
```

## ابتدا از RouterOS پشتیبان بگیرید

```text
/system/backup/save name=before-mikrozia password="یک-رمز-قوی"
/export hide-sensitive file=before-mikrozia
```

هر دو فایل را پیش از هر تغییری با WinBox دانلود کنید.

## فعال‌سازی پشتیبانی Container

1. RouterOS را از کانال `stable` ارتقا دهید.
2. **Extra packages** همان نسخهٔ RouterOS و معماری x86 را از MikroTik دانلود کنید.
3. فایل `container-<version>-x86.npk` را با WinBox آپلود و RouterOS را Reboot کنید.
4. مطمئن شوید بسته موجود است و نسخهٔ آن دقیقاً با RouterOS یکسان است:

```text
/system/package/print where name="container"
```

5. پشتیبانی Container را در Device Mode فعال کنید:

```text
/system/device-mode/update container=yes
```

در CHR، ماشین مجازی را از Hypervisor کاملاً خاموش و دوباره روشن کنید (Reboot نرم
کافی نیست). بررسی کنید:

```text
/system/device-mode/print
```

مقدار `container` باید `yes` باشد.

## بررسی تداخل آدرس

مسیر مبتدی از `172.16.10.0/24` استفاده می‌کند:

```text
172.16.10.1  Bridge در RouterOS
172.16.10.2  کانتینر Mikrozia
```

اگر این Subnet، نام Bridge یا نام VETH قبلاً استفاده شده است، از آن دوباره
استفاده نکنید. مقادیر آزاد انتخاب کنید و آن‌ها را در همهٔ دستورهای زیر یکسان
اعمال کنید.

```text
/ip/address/print
/ip/route/print
/interface/bridge/print
/interface/veth/print
```

## نصب Image نسخه‌دار

Mikrozia به‌صورت Image چندمعماری OCI در Docker Hub منتشر می‌شود. برای محیط
تولیدی از Tag نسخه‌دار استفاده کنید؛ `latest` فقط یک Alias راحت است:

```text
majlot/mikrozia:v1-mikrozia
```

<Callout type="warn">
  پذیرش P1-CHR-01 برای این مسیر روی CHR x86_64 با RouterOS `7.25.1` و Image
  `majlot/mikrozia:v1-mikrozia` به‌صورت واقعی آزموده شده است: دریافت Image،
  شروع و Restart، شبکهٔ داخلی، Mountهای پایدار و SQLite dump/restore جداگانه
  موفق بوده‌اند. آزمون بازگشت میان **دو Tag سازگار متفاوت** هنوز با انتشار Tag
  بعدی انجام می‌شود؛ پیش از ارتقای نسخهٔ اصلی، Backup بگیرید.
</Callout>

این دستورها را به ترتیب در Terminal RouterOS یا WinBox اجرا کنید. فقط اشیای
متعلق به Mikrozia ساخته می‌شوند و با `[Mikrozia:container]` علامت‌گذاری شده‌اند.

### ۱. ساخت پوشه‌های پایدار

پوشهٔ `data` به `/etc/x-ui`، پوشهٔ `cert` به `/root/cert` و پوشهٔ `tmp` برای
فضای موقت Extract متصل می‌شوند. پوشهٔ Root نسخه‌دار را RouterOS هنگام Extract
می‌سازد. این چهار دستور فقط برای نصب تمیز هستند؛ اگر یکی از آن‌ها از قبل وجود
دارد، نصب را تکراری Paste نکنید و ابتدا بخش عیب‌یابی/به‌روزرسانی را بررسی کنید.

```text
/file/add name=containers type=directory
/file/add name=containers/mikrozia type=directory
/file/add name=containers/mikrozia/cert type=directory
/file/add name=containers/mikrozia/tmp type=directory
```

### ۲. ساخت Bridge و VETH

```text
/interface/bridge/add name=br-mikrozia comment="[Mikrozia:container] Bridge"
/ip/address/add address=172.16.10.1/24 interface=br-mikrozia comment="[Mikrozia:container] Gateway"
/interface/veth/add name=veth-mikrozia address=172.16.10.2/24 gateway=172.16.10.1 comment="[Mikrozia:container] VETH"
/interface/bridge/port/add bridge=br-mikrozia interface=veth-mikrozia comment="[Mikrozia:container] Bridge Port"
```

### ۳. افزودن Mountها و متغیرهای محیطی

```text
/container/mounts/add list=MIKROZIA_DATA src=containers/mikrozia/data dst="/etc/x-ui" comment="[Mikrozia:container] Data Mount"
/container/mounts/add list=MIKROZIA_CERT src=containers/mikrozia/cert dst="/root/cert" comment="[Mikrozia:container] Cert Mount"
/container/envs/add list=MIKROZIA_ENV key=XUI_PORT value="2053" comment="[Mikrozia:container] Environment"
/container/envs/add list=MIKROZIA_ENV key=HOME value="/root" comment="[Mikrozia:container] Environment"
/container/envs/add list=MIKROZIA_ENV key=MIKROZIA_ADMIN_USERNAME value="YOUR_ADMIN_USERNAME" comment="[Mikrozia:container] Environment"
/container/envs/add list=MIKROZIA_ENV key=MIKROZIA_ADMIN_PASSWORD value="YOUR_STRONG_PASSWORD" comment="[Mikrozia:container] Environment"
```

<Callout type="warn">
  **Environment کانتینر RouterOS یک انبار پیکربندی است، نه انبار اسرار.** هر
  مقدار در `/container/envs` برای هر کسی که بتواند پیکربندی روتر را بخواند یا
  خروجی بگیرد قابل مشاهده است. برای مدیر یک رمز عبور قوی انتخاب کنید، دسترسی
  به خود روتر و پشتیبان‌هایش را محدود نگه دارید و اگر پیکربندی از کنترل شما
  خارج شد رمز را چرخش دهید. Mikrozia هرگز این مقادیر را در Log چاپ نمی‌کند و
  هرگز از طریق API برنمی‌گرداند.
</Callout>

دو مقدار `MIKROZIA_ADMIN_*` مرجع اصلی حساب مدیر پنل هستند: باید **با هم** تنظیم
شوند و اگر فقط یکی از آن‌ها موجود باشد، پنل اجرا نمی‌شود. قرارداد کامل در
[متغیرهای محیطی](/docs/reference/env-vars#اطلاعات-ورود-مدیر) آمده است.

### ۴. تنظیم Registry و افزودن Container

`/container/config/set` فقط Registry و پوشهٔ Extract را تنظیم می‌کند. Tag
نسخه‌دار در `/container/add` ثابت است و `memory-high`، `memory-max` و
`start-on-boot` مطابق قرارداد Runtime تنظیم شده‌اند.

```text
/container/config/set registry-url="https://registry-1.docker.io" tmpdir=containers/mikrozia/tmp
/container/add remote-image="majlot/mikrozia:v1-mikrozia" interface=veth-mikrozia root-dir=containers/mikrozia/root-v1-mikrozia mountlists="MIKROZIA_DATA,MIKROZIA_CERT" envlist=MIKROZIA_ENV dns="1.1.1.1,8.8.8.8" memory-high=512M memory-max=1024M logging=yes start-on-boot=yes comment="[Mikrozia:container] Container"
```

این دستورها هیچ Rule مربوط به Firewall، NAT، Masquerade، Port Forward یا Routing
اضافه نمی‌کنند. دسترسی خروجی و دسترسی به پنل همچنان تصمیم مدیر RouterOS است.

## انتظار برای Extract و شروع

```text
/container/print detail
/log/print follow-only where topics~"container"
```

Extract ممکن است چند دقیقه طول بکشد. تا پایان آن Container را حذف نکنید و CHR را
خاموش نکنید. سپس آن را Start کنید:

```text
/container/start [find where comment="[Mikrozia:container] Container"]
/container/print detail where comment="[Mikrozia:container] Container"
```

وضعیت باید `running` باشد.

## دسترسی به پنل

پنل داخل کانتینر (`172.16.10.2`) روی `2053/TCP` گوش می‌دهد. اینکه این پورت چگونه
از شبکهٔ مدیریتی شما قابل دسترسی شود، بخشی از طراحی شبکهٔ RouterOS شماست؛ Mikrozia
آن را Publish یا Forward نمی‌کند. به [پورت‌ها و فایروال](/docs/reference/ports-firewall)
مراجعه کنید.

برای یک نمونهٔ دستی و آزموده‌شده که پنل را فقط برای IP مدیر باز و Subscription
را Publish می‌کند، به [پورت‌ها و فایروال](/docs/reference/ports-firewall) بروید.
آن دستورها اختیاری‌اند و Mikrozia آن‌ها را خودکار اجرا نمی‌کند.

## مشخصات ورود اولیه

هیچ حساب پیش‌فرض ثابت و هیچ رمز «ورود اول» تصادفی وجود ندارد. محیط کانتینر
مالک حساب مدیر است:

- اگر `MIKROZIA_ADMIN_USERNAME` و `MIKROZIA_ADMIN_PASSWORD` تنظیم شده باشند، در هر
  بار اجرا حساب مدیر ذخیره‌شده با همان مقادیر هم‌راستا می‌شود؛ با تغییر رمز،
  نشست‌هایی که با رمز قبلی ساخته شده‌اند بی‌اعتبار می‌شوند.
- اگر فقط یکی از آن‌ها تنظیم شده باشد، پنل اجرا نمی‌شود و مقدار ناقص را نام
  می‌برد. هیچ چیز تغییر نمی‌کند.
- اگر هیچ‌کدام تنظیم نشده باشند ولی حسابی موجود باشد، حساب ذخیره‌شده بدون تغییر
  حفظ می‌شود و پنل Log می‌کند که مدیریت آن جای دیگری است.
- اگر هیچ‌کدام تنظیم نشده باشند و هیچ حسابی هم نباشد، پنل اجرا نمی‌شود و هر دو
  مقدار را طلب می‌کند.

وقتی محیط مالک حساب باشد، فرم تغییر رمز در پنل با یک اعلان جایگزین می‌شود و
دستور `x-ui setting -username … -password …` هم تغییر را با پیامی صادقانه رد
می‌کند تا دو منبع حقیقت رقیب به وجود نیاید.

برای تغییر بعدی، دو مقدار Environment را به‌روزرسانی و کانتینر را ری‌استارت
کنید:

```text
/container/envs/set [find where list=MIKROZIA_ENV and key=MIKROZIA_ADMIN_PASSWORD] value="NEW_STRONG_PASSWORD"
/container/restart [find where comment="[Mikrozia:container] Container"]
```

سپس به [نخستین ورود](/docs/guide/first-login) ادامه دهید.

## دیتابیس

SQLite پیش‌فرض است و یک فایل واحد در `/etc/x-ui/x-ui.db` روی Mount پایدار ذخیره
می‌کند. PostgreSQL خارجی اختیاری است و از طریق `/container/envs` در RouterOS
(`XUI_DB_TYPE=postgres` و `XUI_DB_DSN`) تنظیم می‌شود؛ Mikrozia هرگز سرور دیتابیس
را داخل کانتینر نصب نمی‌کند. به [دیتابیس](/docs/reference/database) مراجعه کنید.

## سفارشی‌سازی مقادیر

اگر نام‌ها، Subnet یا مسیر ذخیره‌سازی پیش‌فرض با تنظیمات RouterOS شما تداخل دارد،
آن‌ها را در همهٔ دستورهای بالا یکسان تغییر دهید: Bridge، VETH، آدرس‌های IP،
پوشه‌ها، مبدأ Mountها و `mountlists`. Commentهای `[Mikrozia:container]` را
حفظ کنید تا دستورهای Lifecycle و حذف بتوانند اشیای متعلق به Mikrozia را پیدا
کنند. از Subnet متداخل استفاده نکنید و شیء موجود RouterOS را تغییر نام ندهید.
