درون کانتینر یا از طریق ترمینال، دستور `x-ui` مرکز مدیریت شماست. آن را بدون آرگومان اجرا
کنید تا منوی تعاملی باز شود، یا یک زیردستور به آن بدهید تا عملیات مستقیماً انجام شود.

```bash
x-ui
```

## منوی مدیریت `x-ui`

منو (گزینه‌های `0` تا `16`) وضعیت پنل و سرویس Xray را در بالا نمایش می‌دهد:

| #     | آیتم                                   | کاری که انجام می‌دهد                                       |
| ----- | -------------------------------------- | --------------------------------------------------------- |
| 1     | Reset Username & Password              | تنظیم مشخصات جدید؛ با امکان غیرفعال‌سازی 2FA                |
| 2     | Reset Web Base Path                    | بازنشانی مسیر پایهٔ وب                                     |
| 3     | Reset Settings                         | بازنشانی تنظیمات پنل (اطلاعات کاربران حفظ می‌شود)           |
| 4     | Change Port                            | تغییر پورت پنل                                             |
| 5     | View Current Settings                  | نمایش نام کاربری، پورت، مسیر پایهٔ وب و مسیرهای گواهی       |
| 6–7   | Show RouterOS Start / Stop Command     | نمایش دستورهای `/container/start` و `/container/stop` در RouterOS |
| 8     | Reload Panel & Restart Xray            | بارگذاری مجدد پنل (`SIGHUP`) و ری‌استارت Xray (`SIGUSR1`) بدون ری‌استارت کل کانتینر |
| 9     | Restart Xray Only                      | ارسال `SIGUSR1` برای راه‌اندازی مجدد فقط هستهٔ Xray-core |
| 10    | Check Status                           | وضعیت پنل، Xray و MTProto به همراه دستور بررسی خودکاربودن در RouterOS |
| 11    | Logs Management                        | مشاهده لاگ دیباگ پنل / دستورهای لاگ کانتینر RouterOS        |
| 12–13 | Show RouterOS Enable / Disable Autostart Command | نمایش دستورهای `/container/set` در RouterOS برای `start-on-boot` و `restart-policy` |
| 14    | TLS Certificate Paths                  | انتخاب فایل‌های گواهی ارائه‌شده توسط کاربر برای پنل؛ صدور و تمدید بیرون از کانتینر انجام می‌شود |
| 15    | RouterOS Network Policy Notice         | راهنمای تنظیم فایروال و دسترسی‌ها در RouterOS              |
| 16    | Database Tools                         | تبدیل SQLite `.db` ↔ `.dump` و راهنمای PostgreSQL خارجی   |
| 0     | Exit                                   | خروج از اسکریپت                                            |

برخی از این موارد راهنمای اختصاصی دارند: [گواهی‌های TLS](/docs/config/ssl-certificates)
(گزینه 14)، [تنظیمات پنل](/docs/config/panel) (TLS)، و [پایگاه داده](/docs/reference/database) (PostgreSQL).

## زیردستورهای خط فرمان

برای اسکریپت‌ها و دستورات سریع، `x-ui` زیردستورها را مستقیماً می‌پذیرد:

| دستور                      | عملیات                                              |
| -------------------------- | --------------------------------------------------- |
| `x-ui version`             | نمایش نسخه فعلی Mikrozia                            |
| `x-ui start` / `stop`      | نمایش دستورهای RouterOS (`/container/start` و `/container/stop`)؛ کنترل از سمت RouterOS است |
| `x-ui restart`             | بازبارگذاری سرویس وب پنل و ری‌استارت Xray در داخل کانتینر (خود کانتینر ری‌استارت نمی‌شود) |
| `x-ui restart-xray`        | راه‌اندازی مجدد فقط هستهٔ Xray در داخل کانتینر (`SIGUSR1`) |
| `x-ui status`              | نمایش وضعیت پنل/Xray/MTProto و دستور بررسی Autostart در RouterOS |
| `x-ui settings`            | نمایش تنظیمات جاری                                  |
| `x-ui enable` / `disable`  | نمایش دستورهای RouterOS `/container/set` برای `start-on-boot` و `restart-policy` |
| `x-ui log`                 | مشاهده لاگ دیباگ                                    |
| `x-ui migrateDB [file]`    | تبدیل دیتابیس SQLite میان .db و .dump               |

## به‌روزرسانی

در معماری Mikrozia، به‌روزرسانی فقط و فقط از طریق تعویض Image یا کانتینر انجام می‌شود. تمام اسکریپت‌های ناامن آپدیت درجا (`update.sh`) که از درون کانتینر اجرا می‌شدند به‌طور کامل حذف شده‌اند تا ساختار سیستم‌عامل کانتینر (RootFS) دست‌نخورده مانده و پایداری RouterOS تضمین شود.

مراحل به‌روزرسانی:
1. دریافت تگ جدید ایمیج Mikrozia (مثلاً از داکر هاب `majlot/mikrozia`).
2. توقف کانتینر فعلی و ساخت مجدد آن با ایمیج جدید، همراه با اتصال همان Mountهای پایدار قبلی (`/etc/x-ui` و `/root/cert`).
3. روشن کردن کانتینر جدید.

پایگاه داده، کاربران و گواهی‌های شما در پوشه‌های پایدار مانت‌شده کاملاً محفوظ می‌مانند. همواره پیش از ارتقای نسخه‌های اصلی، یک [پشتیبان](/docs/operations/backup-restore) تهیه کنید.

### بازگردانی به‌روزرسانی ایمیج

اگر ایمیج جدید در اعتبارسنجی شکست خورد، کانتینر را متوقف نگه دارید، آن را با تگ نسخه‌ی قبلی ایمیج بازسازی کنید و همان مانت‌های `/etc/x-ui` و `/root/cert` را دوباره استفاده کنید. پایگاه‌داده و گواهی‌ها بخشی از ایمیج نیستند. اگر ایمیج جدید قبلاً Schema پایگاه‌داده را مهاجرت داده است، پیش از شروع ایمیج قدیمی، پشتیبان پایگاه‌داده‌ی پیش از به‌روزرسانی را بازیابی کنید؛ پنل قدیمی هرگز نباید Schema جدیدتر را باز کند. بازگردانی ایمیج هرگز نیازی به کپی داده‌ها به RootFS ایمیج ندارد.

<Callout type="info">
  کانتینر Mikrozia هرگز فایل‌سیستم خود را در حین اجرا دستکاری نمی‌کند. تعویض ایمیج، استقرار تمیز، ایمن و تکرارپذیر را تضمین می‌نماید.
</Callout>

برای ری‌استارت کامل خود کانتینر از Terminal یا WinBox در RouterOS اجرا کنید: `/container/restart [find where comment="[Mikrozia:container] Container"]`.

## حذف

برای حذف Mikrozia در RouterOS:
1. توقف کانتینر: `/container/stop [find where comment="[Mikrozia:container] Container"]`
2. حذف کانتینر: `/container/remove [find where comment="[Mikrozia:container] Container"]`

<Callout type="warn">
  حذف کانتینر در RouterOS پوشه‌های حافظه پایدار (`/etc/x-ui` و `/root/cert`) را به‌طور خودکار پاک نمی‌کند. پاک‌سازی داده‌های کاربران، دیتابیس و گواهی‌ها همواره باید یک اقدام جداگانه، آگاهانه و صریح توسط مدیر سیستم روی حافظه ذخیره‌سازی باشد تا از هرگونه از دست رفتن تصادفی اطلاعات جلوگیری شود.
</Callout>
