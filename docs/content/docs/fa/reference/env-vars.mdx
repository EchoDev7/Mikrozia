Mikrozia پیکربندی زمان‌اجرای خود را از متغیرهای محیطی می‌خواند. در
RouterOS Container آن‌ها را در `/container/envs` تعریف کرده و به `envlist`
کانتینر متصل کنید؛ برای توسعه محلی با Docker، آن‌ها را در `docker-compose.yml` یا
`docker run -e` تنظیم کنید. برای اعمال تغییرات محیطی، کانتینر را با همان مانت‌های
پایدار (`/etc/x-ui` و `/root/cert`) بازسازی کنید.

## وضعیت و معیارهای RouterOS API

داشبورد می‌تواند یک درخواست فقط‌خواندنی از RouterOS API بومی را فقط از شبکهٔ
داخلی کانتینر به روتر روی TCP/8728 اجرا کند. این مقادیر اختیاری هستند؛ هر سه
را تنظیم کنید یا هیچ‌کدام را تنظیم نکنید. پیکربندی ناقص نامعتبر است. Mikrozia
سرویس API را فعال نمی‌کند، کاربر نمی‌سازد و تنظیمات روتر را تغییر نمی‌دهد.

| متغیر | پیش‌فرض | توضیح |
| --- | --- | --- |
| `MIKROZIA_ROUTEROS_API_HOST` | — | نشانی عددی خصوصی (literal private IPv4/IPv6) روتر برای API (بدون نام میزبان، zone، loopback یا link-local). |
| `MIKROZIA_ROUTEROS_API_USERNAME` | — | نام حساب اختصاصی فقط‌خواندنی RouterOS API (فقط دسترسی‌های `read,api`). |
| `MIKROZIA_ROUTEROS_API_PASSWORD` | — | رمز حساب RouterOS API. |
| `MIKROZIA_ROUTEROS_CONTAINER_COMMENT` | — | comment یکتای دقیق کانتینر Mikrozia در RouterOS؛ خواندن فقط‌خواندنی لاگ کانتینر را فعال می‌کند. |
| `MIKROZIA_ROUTEROS_RESTART_USERNAME` | — | نام حساب عملیاتی جداگانهٔ RouterOS API برای Restart Container اختیاری. به مجوزهای read، write و api نیاز دارد؛ دسترسی را فقط به IP داخلی کانتینر محدود کنید. |
| `MIKROZIA_ROUTEROS_RESTART_PASSWORD` | — | رمز حساب عملیاتی جداگانه و اختیاری؛ از حساب فقط‌خواندنی استفاده نکنید. |

از مقادیر جایگزین مانند `172.16.10.1`، `<READ_ONLY_API_USER>` و
`<SET_A_SECRET_VALUE>` استفاده کنید. رمز فقط هنگام بررسی در حافظهٔ فرایند
نگه‌داری می‌شود و در پایگاه‌داده ذخیره یا از API پنل بازگردانده نمی‌شود. مقادیر
`/container/envs` برای مدیران روتر قابل مشاهده‌اند و مخزن امن اسرار نیستند.
این یکپارچه‌سازی هر ۱۵ ثانیه با مهلت ۴ ثانیه و آستانهٔ کهنگی ۳۰ ثانیه دستور
فقط‌خواندنی `/system/resource/print` را برای فیلدهای `uptime`، `cpu-load`،
`cpu-count`، `cpu-frequency`، `total-memory` و `free-memory` می‌خواند؛ خواندن
لاگ‌های کانتینر RouterOS و آمار VETH سمت RouterOS همچنان در مراحل آینده قرار دارند.

## معیارهای شبکهٔ کانتینر

| متغیر | پیش‌فرض | توضیح |
| --- | --- | --- |
| `MIKROZIA_CONTAINER_INTERFACE` | — | نام دقیق اینترفیس برای Overall Speed داشبورد، وقتی جمع‌آوری خودکار هیچ اینترفیس قابل‌استفاده‌ای پیدا نمی‌کند. الگوی مجاز `^[A-Za-z0-9._-]{1,63}$` است؛ `lo` و `lo0` رد می‌شوند. |

با تنظیم این مقدار، Mikrozia فقط همان اینترفیس را از namespace شبکهٔ خود
کانتینر (`/proc/net/dev`) می‌خواند و هیچ شمارندهٔ اینترفیسی را از RouterOS API
دریافت نمی‌کند. نام نامعتبر یا ناموجود، Overall Speed را بدون fallback به
اینترفیس دیگر در حالت Unavailable نگه می‌دارد. Upload برابر TX و Download برابر
RX است. روی میزبانی که جمع‌آوری خودکار از قبل یک NIC قابل‌استفاده پیدا کرده، این
متغیر اثری ندارد.

## اطلاعات ورود مدیر

محیط کانتینر **مرجع اصلی** حساب مدیر پنل است. هیچ مقدار پیش‌فرض ثابت
`admin/admin` و هیچ رمز تصادفی «ورود اول» وجود ندارد.

| متغیر                     | پیش‌فرض | توضیح                                                              |
| ------------------------- | ------- | ------------------------------------------------------------------ |
| `MIKROZIA_ADMIN_USERNAME` | —       | نام کاربری مدیر. باید همراه رمز عبور تنظیم شود.                  |
| `MIKROZIA_ADMIN_PASSWORD` | —       | رمز عبور مدیر. باید همراه نام کاربری تنظیم شود.                   |

پنل در هر بار اجرا حساب مدیر ذخیره‌شده را با این دو مقدار هم‌راستا می‌کند: نام
کاربری و رمز عبور به‌روزرسانی می‌شوند و با تغییر رمز عبور، نشست‌هایی که با رمز
قبلی ساخته شده‌اند بی‌اعتبار می‌شوند. حساب‌های موجود هرگز به‌طور خودکار حذف یا
بازنشانی نمی‌شوند.

| وضعیت                                                                 | رفتار                                                                                          |
| --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| هر دو مقدار تنظیم شده                                              | محیط مالک حساب است؛ در هر اجرا حساب ذخیره‌شده هم‌راستا می‌شود.                                    |
| فقط یکی از دو مقدار تنظیم شده                                      | پنل اجرا نمی‌شود و مقدار ناقص را نام می‌برد. هیچ چیز تغییر نمی‌کند.                            |
| هیچ‌کدام تنظیم نشده و حسابی موجود است                              | حساب ذخیره‌شده بدون تغییر حفظ می‌شود و پنل Log می‌کند که مدیریت آن جای دیگری است.                 |
| هیچ‌کدام تنظیم نشده و هیچ حسابی وجود ندارد                         | پنل اجرا نمی‌شود و هر دو مقدار را طلب می‌کند.                                                   |
| هیچ‌کدام تنظیم نشده و حساب ذخیره‌شده هنوز همان `admin` / `admin` قدیمی است | پنل اجرا نمی‌شود و حساب ذخیره‌شده را نگه می‌دارد.                                                |

وقتی محیط مالک حساب باشد، زبانهٔ **امنیت** در پنل به‌جای فرم رمز عبور یک اعلان
نمایش می‌دهد و تغییر رمز از داخل پنل با پیامی صادقانه رد می‌شود — محیط در
اجرای بعد آن را بازنویسی می‌کند.

<Callout type="warn">
  **Environment کانتینر RouterOS یک انبار پیکربندی است، نه انبار اسرار.** هر
  مقدار در `/container/envs` برای هر کسی که بتواند پیکربندی روتر را بخواند یا
  خروجی بگیرد قابل مشاهده است. یک رمز عبور قوی برای مدیر انتخاب کنید و دسترسی
  و پشتیبان‌های خودِ روتر را محافظت کنید. Mikrozia هرگز این مقادیر را در Log
  چاپ نمی‌کند، هرگز از طریق API برنمی‌گرداند و هرگز داخل Image نمی‌نویسد.
</Callout>

## پایگاه‌داده

| Variable                 | Default     | Description                                                          |
| ------------------------ | ----------- | -------------------------------------------------------------------- |
| `XUI_DB_TYPE`            | `sqlite`    | بک‌اند: `sqlite`، یا `postgres` (همچنین `postgresql` / `pg` را می‌پذیرد). |
| `XUI_DB_FOLDER`          | `/etc/x-ui` | پوشه‌ی فایل پایگاه‌داده‌ی SQLite (`x-ui.db`).                     |
| `XUI_DB_DSN`             | —           | رشته اتصال PostgreSQL در قالب URI (`postgres://`/`postgresql://`) یا Keyword/Value (پیشرفته؛ وقتی `XUI_DB_TYPE=postgres` باشد). گواهی‌های TLS را زیر `/root/cert` قرار دهید (`sslmode=verify-full` پیشنهادی)؛ `PGPASSWORD` پشتیبانی نمی‌شود. |
| `XUI_DB_MAX_OPEN_CONNS`  | —           | حداکثر اتصالات باز در استخر PostgreSQL.                         |
| `XUI_DB_MAX_IDLE_CONNS`  | —           | حداکثر اتصالات بی‌کار در استخر PostgreSQL.                         |

مسیر پیش‌فرض پایگاه‌داده‌ی SQLite برابر `/etc/x-ui/x-ui.db` است. برای جزئیات
‏SQLite ↔ PostgreSQL به [پایگاه‌داده](/docs/reference/database) مراجعه کنید.

## رمزگذاری توکن نود

توکن‌های حامل (bearer) API نود — و توکن ذخیره‌شده‌ی PIA — به‌صورت پیش‌فرض به شکل
متن ساده نگهداری می‌شوند. رمزگذاری در حالت سکون اختیاری است و به‌صورت ایمن شکست
می‌خورد: با هر حالتی به‌جز `off`، اگر پنل نتواند کلیدی را بارگذاری کند، اجرا نمی‌شود.

| Variable                  | Default                         | Description                                                                                                                                                            |
| ------------------------- | ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `NODE_TOKEN_ENCRYPTION`   | `off`                           | ‏`off`، `migration` (خواندن هم متن ساده و هم متن رمزشده را می‌پذیرد، نوشتن همیشه رمز می‌کند) یا `required` (نوشتن یکسان، اما بدون کلید اجرا شکست می‌خورد). به نبودِ پیشوند `XUI_` توجه کنید. |
| `XUI_NODE_TOKEN_KEY_FILE` | `/etc/x-ui/node_token_key.json` | حلقه‌کلید JSON با دسترسی `0600` یا محدودتر (در ویندوز بررسی نمی‌شود و مجوزهای NTFS از آن محافظت می‌کنند). نخست همین بارگذاری می‌شود.                                     |
| `XUI_NODE_TOKEN_KEY`      | —                               | یک کلید ۳۲ بایتی base64 که فقط هنگام شکست بارگذاری فایل کلید خوانده می‌شود. شناسه‌ی کلید آن ثابت و برابر `env` است، پس امکان چرخش ندارد.                                |

فایل کلید، کلید فعال به‌همراه هر کلید قدیمی‌ای را که هنوز برای رمزگشایی لازم است نام می‌برد:

```json
{ "active": "k1", "keys": { "k1": "<base64 32-byte key>" } }
```

کلید را با `openssl rand -base64 32` بسازید؛ کلیدها هرگز به‌عنوان آرگومان خط فرمان
پذیرفته نمی‌شوند. پس از فعال‌کردن یک حالت، ردیف‌هایی را که از پیش در پایگاه‌داده
هستند با کلید فعال دوباره رمز کنید:

```bash
x-ui encrypt-tokens
```

این دستور ردیف‌های نود را پوشش می‌دهد؛ توکن PIA در نوبت بعدیِ خواندن دوباره رمز
می‌شود. برای چرخش کلید، کلید جدید را به `keys` اضافه کنید، `active` را به آن اشاره
دهید، کلید قدیمی را برای رمزگشایی نگه دارید و دوباره `x-ui encrypt-tokens` را اجرا کنید.

## حافظه و پروفایلینگ

پنل با استفاده از `GOGC` و آزادسازی‌های دوره‌ای، مصرف حافظه را پایین نگه می‌دارد.
این‌ها تنظیمات پیشرفته‌ای هستند — مگر اینکه در حال تنظیم دقیق یک میزبان با منابع
محدود باشید، آن‌ها را تنظیم‌نشده رها کنید.

| Variable                      | Default | Description                                                       |
| ----------------------------- | ------- | ----------------------------------------------------------------- |
| `XUI_GOGC`                    | —       | درصد هدف GC در Go؛ کمتر = RAM کمتر، CPU اندکی بیشتر.     |
| `XUI_MEMORY_RELEASE_INTERVAL` | —       | فاصله‌ی زمانی فراخوانی‌های `FreeOSMemory` بر حسب دقیقه؛ مقدار `0` آن را غیرفعال می‌کند.               |
| `XUI_MEMORY_LIMIT`            | —       | محدودیت نرم حافظه‌ی Go بر حسب **MiB**.                                  |
| `GOMEMLIMIT`                  | —       | محدودیت نرم با نحو Go (مثلاً `400MiB`)؛ بر مورد بالا اولویت دارد.|
| `XUI_PPROF`                   | `false` | در دسترس قرار دادن پروفایلینگ pprof روی `127.0.0.1:6060`.                       |

## پایشگر سلامت تونل

نگهبان اختیاری: یک URL را پروب می‌کند (به‌صورت اختیاری **از طریق** یک ورودی محلی
‏Xray) و پس از خرابی‌های مکرر، Xray را ری‌استارت می‌کند. هر ری‌استارت همه‌ی
کلاینت‌های متصل را قطع می‌کند، پس آن را آگاهانه فعال کنید.

| Variable                      | Default                                      | Description                                                       |
| ----------------------------- | -------------------------------------------- | ----------------------------------------------------------------- |
| `XUI_TUNNEL_HEALTH_MONITOR`   | `false`                                      | فعال‌سازی پایشگر.                                               |
| `XUI_TUNNEL_HEALTH_PROXY`     | —                                            | پروکسی‌ای که پروب از طریق آن ارسال می‌شود، مثلاً `socks5://127.0.0.1:1080`. خالی = فقط اتصال میزبان را بررسی می‌کند. |
| `XUI_TUNNEL_HEALTH_URL`       | `https://www.cloudflare.com/cdn-cgi/trace`   | URLی که پروب می‌شود.                                                     |
| `XUI_TUNNEL_HEALTH_INTERVAL`  | `30s`                                        | فاصله‌ی زمانی بین پروب‌ها.                                         |
| `XUI_TUNNEL_HEALTH_TIMEOUT`   | `10s`                                        | مهلت زمانی هر پروب.                                              |
| `XUI_TUNNEL_HEALTH_FAILURES`  | `3`                                          | تعداد خرابی‌های متوالی پیش از یک ری‌استارت.                          |
| `XUI_TUNNEL_HEALTH_COOLDOWN`  | `5m`                                         | حداقل تأخیر بین ری‌استارت‌ها.                                 |

## ACME

### `MIKROZIA_CF_API_TOKEN`

توکن API کم‌دامنهٔ Cloudflare که برای صدور گواهی و تمدید خودکار به روش
**DNS-01** استفاده می‌شود. اختیاری است: توکن را می‌توان به‌صورت تعاملی هم ذخیره
کرد (`x-ui` → `14 — TLS Certificates` → `4` یا
`x-ui acme cloudflare setup --domain <domain>`) که روش ترجیحی است، چون مقدارِ
داخل RouterOS Environment در پیکربندی روتر قابل مشاهده است. `--stdin` صریح فقط
برای ورودی عمداً غیرتعاملی و یک‌خطی پشتیبانی می‌شود؛ ورودی استاندارد ارثی عمومی
رد می‌شود.

توکن هرگز Log نمی‌شود، هرگز به‌صورت متن ساده از API برنمی‌گردد، هرگز در
تنظیمات تولیدشده جا نمی‌گیرد و هرگز روی ریشهٔ تغییرناپذیر Image نوشته نمی‌شود.
با سطح دسترسی `0600` روی Mount پایدار گواهی ذخیره می‌شود؛ بنابراین پس از تعویض
Image و بازگردانی باقی می‌ماند.

<Callout type="warn">
  توکنی که در RouterOS Environment باشد برای هر کسی که بتواند پیکربندی روتر را
  بخواند یا Export کند قابل مشاهده است. ورودی تعاملی پنهان
  `x-ui acme cloudflare setup --domain <domain>` را ترجیح دهید، توکن را به همان
  یک Zone محدود کنید (`Zone → DNS → Edit` و
  `Zone → Zone → Read`) و وقتی فرد دیگری به روتر دسترسی داشت آن را چرخش دهید.
</Callout>
