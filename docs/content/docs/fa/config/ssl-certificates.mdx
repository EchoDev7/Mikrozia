گواهی TLS به شما اجازه می‌دهد **پنل** را روی HTTPS ارائه کنید (تا ورود و ترافیک API
رمزنگاری شود) و TLS را روی **Inboundها** (VLESS-TLS، Trojan، Shadowsocks-TLS و
مانند آن) پایان دهید. Mikrozia یک کلاینت ACME با نسخهٔ Pin‌شده داخل Image دارد، پس
می‌توانید بدون نصب چیزی روی روتر و بدون اجرای صادرکنندهٔ گواهی روی خود RouterOS،
گواهی صادر و تمدید کنید.

دو روش صدور پشتیبانی می‌شود:

| روش                    | پورت عمومی ۸۰ | تمدید       | مناسب برای                                    |
| ---------------------- | -------------- | ----------- | --------------------------------------------- |
| **HTTP-01** (دستی)     | لازم است      | دستی        | دامنه‌های تک‌بار، بدون دسترسی به API دیجیتال‌ساز. |
| **Cloudflare DNS-01**  | لازم نیست     | خودکار      | دامنه‌هایی که DNS آن‌ها روی Cloudflare است.  |

<Callout type="warn">
  **دسترس‌پذیری** گواهی بر عهدهٔ خود شماست. Mikrozia هرگز Rule مربوط به Firewall،
  NAT، Port Forwarding، Routing، Address List یا Cloud Security در RouterOS را — چه
  از پنل، چه از منوی شل، چه از این مستندات — ایجاد، تغییر، حذف، فعال یا غیرفعال
  نمی‌کند. توکن Cloudflare هرگز Log نمی‌شود، هرگز به‌صورت متن ساده از API
  برنمی‌گردد، هرگز در تنظیمات تولیدشده جا نمی‌گیرد و هرگز روی ریشهٔ تغییرناپذیر
  Image نوشته نمی‌شود.
</Callout>

## گواهی‌ها کجا ذخیره می‌شوند

همهٔ داده‌های ACME روی Mount پایدار گواهی قرار می‌گیرند؛ بنابراین پس از تعویض
Image و بازگردانی (Rollback) باقی می‌مانند:

```text
/root/cert/vpn.example.com/fullchain.pem   # گواهی صادرشده به‌همراه زنجیره
/root/cert/vpn.example.com/privkey.pem      # کلید خصوصی (0600)
/root/cert/.acme.sh/                         # حساب ACME، وضعیت هر دامنه و وضعیت تمدید
```

پس از صدور موفق، پنل و سرور Subscription به‌طور خودکار به
`/root/cert/<domain>/fullchain.pem` و `/root/cert/<domain>/privkey.pem` اشاره
می‌کنند. فیلدهای **Public Key Path** و **Private Key Path** در
[تنظیمات پنل](/docs/config/panel#tls) همچنان قابل ویرایش‌اند، پس گواهی‌ای که
جای دیگری قرار دارد نیز قابل استفاده است.

## صدور گواهی: HTTP-01 (دستی)

اعتبارسنجی HTTP-01 به پورت TCP ۸۰ نیاز دارد تا **فقط در طول اجرای صدور** از
اینترنت به کانتینر برسد.

<Steps>

### پورت ۸۰ را به کانتینر برسانید

با Ruleای که خودتان مالک آن هستید، پورت عمومی TCP/۸۰ را به پورت ۸۰ کانتینر
Forward کنید. پنل Mikrozia هرگز این Rule را برای شما نمی‌نویسد. پس از صدور
گواهی آن را ببندید؛ تمدید دستی است و در زمان تمدید دوباره باز می‌کنید.

### پیش‌نیازها را بررسی کنید

```bash
x-ui acme check --http --domain panel.example.com
```

خروجی، کلاینت پیوست‌شده، خانهٔ حساب ACME و نتیجهٔ تفکیک محلی DNS را گزارش
می‌کند. Mikrozia از داخل کانتینر نمی‌تواند دسترس‌پذیری عمومی HTTP-01 را بررسی
کند. اپراتور RouterOS باید موقتاً TCP 80 را از اینترنت عمومی در دسترس قرار دهد.
این دستور هرگز سیاست RouterOS را مدرک دسترس‌پذیری عمومی نمی‌داند و هیچ Rule
روتری را تغییر نمی‌دهد.

### گواهی را صادر کنید

```bash
x-ui acme issue --http --domain panel.example.com
```

یا از منوی شل: `x-ui` را اجرا کنید، **`14 — TLS Certificates`** و سپس
**`3 — Issue or renew a certificate with HTTP-01 (manual)`** را انتخاب کنید.

کلاینت در اولین استفاده حساب ACME را ثبت می‌کند (برای دریافت اعلان انقضا
`--email` اضافه کنید)، دامنه را اعتبارسنجی می‌کند و جفت گواهی را روی Mount پایدار
نصب می‌کند. مسیرهای TLS پنل و Subscription تنها پس از اعتبارسنجی موفق جفت جدید
به‌روزرسانی می‌شوند؛ اگر چیزی شکست بخورد، گواهی و تنظیمات قبلی دست‌نخورده
می‌مانند.

برای جفت تغییرکرده و معتبر، همان تراکنش هر چهار مسیر TLS پنل و Subscription را
به‌روزرسانی می‌کند و پنل، شنوندهٔ Subscription و Xray را دقیقاً یک‌بار بارگذاری
مجدد می‌کند؛ Restart جدا لازم نیست. شکست Reload گزارش می‌شود و جفت گواهی و
تنظیمات قبلی بازیابی می‌شوند.

</Steps>

<Callout type="info">
  گواهی‌های HTTP-01 **به‌صورت دستی تمدید می‌شوند**. پنل هرگز تمدید HTTP-01 را
  زمان‌بندی نمی‌کند، چون به دسترس‌پذیری پورت ۸۰ نیاز دارد که فقط شما می‌توانید
  فراهم کنید. وقتی گواهی نزدیک انقضا شد، گام‌های بالا را با پورت ۸۰ باز تکرار
  کنید.
</Callout>

## صدور گواهی: Cloudflare DNS-01 (خودکار)

اعتبارسنجی DNS-01 به پورت عمومی نیاز ندارد. پنل رکورد TXT با نام
`_acme-challenge` را از طریق API Cloudflare اضافه و حذف می‌کند؛ بنابراین هیچ
ترافیکی برای اعتبارسنجی به روتر نمی‌رسد.

### یک توکن API با حداقل دسترسی بسازید

در پنل Cloudflare یک API Token بسازید با:

- **دسترسی‌ها:** `Zone → DNS → Edit` و `Zone → Zone → Read`.
- **منابع Zone:** `Include → Specific zone → فقط دامنهٔ خودتان`.

توکنی که بتواند DNS همهٔ Zoneها را ویرایش کند لازم نیست و نباید استفاده شود.

### توکن را ذخیره کنید

`x-ui` را اجرا کنید، **`14 — TLS Certificates`** و سپس
**`4 — Cloudflare DNS-01 setup and automatic renewal`** را انتخاب کنید. توکن از
یک ورودی پنهان خوانده می‌شود و هرگز روی صفحه نمایش داده نمی‌شود.

همین جریان ورودی پنهان از خط فرمان:

```bash
x-ui acme cloudflare setup --domain panel.example.com
```

برای ورودی عمداً غیرتعاملی، از `MIKROZIA_CF_API_TOKEN` استفاده کنید یا فقط با
`--stdin` صریح یک خط را به ورودی استاندارد بدهید. ورودی استاندارد ارثی عمومی،
ورودی پنهان محسوب نمی‌شود.

توکن هرگز به‌عنوان آرگومان خط فرمان پذیرفته نمی‌شود؛ پس نه در تاریخچهٔ Shell و نه
در فهرست پردازه‌ها ثبت می‌شود. با سطح دسترسی `0600` داخل `/root/cert/.acme.sh/`
ذخیره می‌شود و تنها از طریق محیط پردازهٔ فرزند به کلاینت ACME داده می‌شود.

### گواهی را صادر کنید

```bash
x-ui acme issue --dns --domain panel.example.com
```

پس از صدور موفق، پنل دامنه را در حالت DNS-01 نگه می‌دارد؛ یعنی تمدید زمان‌بندی‌شده
شامل آن می‌شود.

### تمدید و بارگذاری مجدد

پنل هر دوازده ساعت یک‌بار دامنه‌های DNS-01 را بررسی می‌کند. کلاینت پیوست‌شده فقط
گواهی‌ای را که به انقضا نزدیک است دوباره صادر می‌کند؛ بنابراین این بازه، فاصلهٔ
بررسی است نه فاصلهٔ صدور. وقتی فایل‌های نصب‌شده واقعاً تغییر کنند، پنل مسیرهای
گواهی را به‌روزرسانی و شنونده‌ها را بارگذاری مجدد می‌کند؛ اگر چیزی تغییر نکرده
باشد، هیچ بارگذاری مجددی انجام نمی‌شود و ترافیک قطع نمی‌شود.

### چرخش توکن

در Cloudflare توکن تازه بسازید و همان دستور را دوباره اجرا کنید. توکن جدید جای
توکن قبلی را می‌گیرد؛ سپس می‌توانید توکن قبلی را در Cloudflare باطل کنید.

<Callout type="info">
  توکن API Cloudflare را می‌توان به‌صورت متغیر محیطی کانتینر
  `MIKROZIA_CF_API_TOKEN` هم داد. مقادیر RouterOS Environment برای هر کسی که
  بتواند پیکربندی RouterOS را بخواند یا Export کند قابل مشاهده است؛ این محیط
  انبار پیکربندی است، نه انبار اسرار. پیش از استفاده،
  [هشدار حساسیت](/docs/reference/env-vars#mikrozia-cf-api-token) را بخوانید.
</Callout>

## استفاده از گواهی‌ای که از قبل دارید

درون‌ریزی یک گواهی موجود کاملاً پشتیبانی می‌شود و به حساب ACME نیاز ندارد:

- `x-ui` را اجرا کنید، **`14 — TLS Certificates`** و سپس
  **`2 — Set certificate paths for the panel (manual import)`** را انتخاب کنید.
- یا از خط فرمان:

  ```bash
  x-ui cert -webCert /root/cert/vpn.example.com/fullchain.pem \
    -webCertKey /root/cert/vpn.example.com/privkey.pem
  x-ui restart
  ```

- یا `webCertFile` و `webKeyFile` را در
  [تنظیمات پنل](/docs/config/panel#tls) تنظیم کنید.

پنل تنها زمانی به HTTPS سوئیچ می‌کند که **هر دو** مسیر تنظیم شده و هر دو فایل
قابل خواندن باشند. برای پاک‌کردن آن‌ها `x-ui cert -reset` را اجرا کنید.

## استفاده از گواهی در Inboundها

وقتی TLS را روی یک Inbound فعال می‌کنید، همان مسیرهای گواهی و کلید (یا محتوای
آن‌ها) را در تنظیمات TLS آن Inbound ارجاع دهید. به
[Inboundها](/docs/config/inbounds) و [ترنسپورت‌ها](/docs/config/transports)
مراجعه کنید. Inboundهای [REALITY](/docs/config/reality) به هیچ گواهی‌ای نیاز
ندارند؛ آن‌ها TLS یک سایت واقعی را قرض می‌گیرند.

## مرجع خط فرمان

```text title="x-ui acme"
x-ui acme status                       # دامنه، روش اعتبارسنجی، انقضا، روش تمدید
x-ui acme check --http --domain <d>   # پیش‌نیازهای HTTP-01 (فقط خواندنی)
x-ui acme check --dns  --domain <d>   # پیش‌نیازهای DNS-01 (فقط خواندنی)
x-ui acme issue --http --domain <d>   # صدور و نصب با HTTP-01
x-ui acme issue --dns  --domain <d>   # صدور و نصب با DNS-01
x-ui acme renew --domain <d>          # تمدید و نصب، فقط اگر فایل‌ها تغییر کرده باشند
x-ui acme cloudflare setup --domain <d> --stdin
```

`--email <address>` نشانی تماس حساب ACME را اضافه می‌کند و `--staging` از
دایرکتوری آزمایشی ACME استفاده می‌کند (گواهی‌های نامعتبر که هرگز از سهمیهٔ صدور
کم نمی‌کنند — مناسب برای نخستین آزمون).

## عیب‌یابی

- **اعتبارسنجی HTTP-01 ناموفق بود.** پورت ۸۰ هنگام اجرای صدور از اینترنت در
  دسترس نبوده، یا سرویس دیگری روی پورت ۸۰ پاسخ می‌داد. از داخل کانتینر
  `x-ui acme check --http --domain <d>` را اجرا کنید.
- **اعتبارسنجی DNS-01 ناموفق بود.** توکن دسترسی `Zone → DNS → Edit` برای آن
  Zone را ندارد، یا رکورد هنوز منتشر نشده است. Zone باید در Cloudflare فعال
  باشد.
- **گواهی فعال نشد.** خطای صدور یا تمدید را بخوانید. شکست Apply/Reload جفت
  گواهی قبلی و هر چهار مسیر TLS قبلی را بازیابی می‌کند؛ پس از رفع علت، دستور
  ACME را دوباره اجرا کنید و وضعیت را با `x-ui acme status` بررسی کنید.
- **انقضا.** گواهی‌ها منقضی می‌شوند. انقضا را با ابزار خودتان پایش کنید و پیش از
  انقضا تمدید کنید؛ پنل فایل‌ها را از مسیرهای پیکربندی‌شده می‌خواند.

## منسوخ: جریان گواهی Reverse Proxy روی RouterOS

راهنمای پیشین از شما می‌خواست TLS را با گواهی متعلق به RouterOS (یا جریان
`certbot` روی روتر) پایان دهید. این جریان از مستندات جاری منسوخ شده است: گواهی‌ها
را کلاینت ACME پیوست‌شده صادر می‌کند و زیر `/root/cert` نگه می‌دارد، و Mikrozia
هرگز کلید خصوصی RouterOS را به داخل کانتینر نمی‌آورد. نصب‌هایی که هنوز از جریان
قدیمی استفاده می‌کنند دست‌نخورده کار می‌کنند — به‌روزرسانی Image چیزی را حذف یا
بازنویسی نمی‌کند. ارائهٔ پنل از طریق یک میزبان Reverse Proxy جدا همچنان
پشتیبانی می‌شود؛ به [Reverse proxy](/docs/operations/reverse-proxy) مراجعه کنید.
