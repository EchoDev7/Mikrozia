با فعال‌سازی **مدیریت خودکار NAT در میکروتیک (Managed RouterOS NAT)**، هر زمان که در پنل میکروزیا یک اینباند محلی جدید بسازید، پورت یا پروتکل آن را ویرایش کنید، آن را خاموش/روشن کنید یا حذف نمایید، رول `dst-nat` متناظر آن به صورت خودکار روی روتر میکروتیک (RouterOS) اعمال می‌شود.

<Callout type="info">
  این قابلیت به‌صورت پیش‌فرض **خاموش** است و تنها در صورت فعال‌سازی دستی توسط مدیر کار می‌کند. میکروزیا **فقط** رول‌های دارای برچسب اختصاصی `mikrozia:managed:inbound:<id>:<proto>` را مدیریت می‌کند و هرگز رول‌های دستی شما در میکروتیک را تغییر نمی‌دهد یا حذف نمی‌کند.
</Callout>

## پیش‌نیازها

- روتر MikroTik RouterOS v7 (یا CHR) که کانتینر میکروزیا روی آن اجرا می‌شود.
- دسترسی شبکه داخلی (Private IP) از داخل کانتینر میکروزیا به گیت‌وی/بریج میکروتیک (مثلاً `172.16.10.1`).
- یک کاربر اختصاصی API در میکروتیک با حداقل دسترسی (`read,write,api`).

## راه‌اندازی گام‌به‌گام در میکروتیک

<Steps>

<Step>
### ساخت گروه و کاربر اختصاصی API

در ترمینال میکروتیک (از طریق WinBox یا SSH) یک گروه با حداقل دسترسی لازم و یک کاربر اختصاصی برای میکروزیا بسازید:

```bash
/user/group/add name=mikrozia-nat policy=read,write,api
/user/add name=mikrozia-nat group=mikrozia-nat password="YOUR_STRONG_PASSWORD"
```

<Callout type="warn">
  هرگز از کاربر `admin` با دسترسی `full` برای این اتصال استفاده نکنید. دسترسی `read,write,api` برای مدیریت رول‌های NAT کافی است.
</Callout>
</Step>

<Step>
### فعال‌سازی سرویس API فقط برای ساب‌نت کانتینر

سرویس API میکروتیک را فعال کنید و دسترسی آن را **فقط** به ساب‌نت خصوصی بریج کانتینر (مثلاً `172.16.10.0/24`) محدود نمایید تا از اینترنت قابل دسترسی نباشد:

```bash
/ip/service/set api disabled=no port=8728 address=172.16.10.0/24
```

اگر در فایروال ورودی (`chain=input`) میکروتیک ترافیک بریج کانتینر به خود روتر مسدود است، یک رول اجازه فقط برای پورت `8728` از ساب‌نت کانتینر اضافه کنید:

```bash
/ip/firewall/filter/add chain=input action=accept protocol=tcp dst-port=8728 src-address=172.16.10.0/24 comment="Allow Mikrozia container API"
```
</Step>

<Step>
### بررسی لیست اینترفیس WAN (اختیاری)

به‌صورت پیش‌فرض میکروزیا رول‌های `dst-nat` را با شرط `in-interface-list=WAN` می‌سازد. بررسی کنید که اینترفیس متصل به اینترنت در میکروتیک عضو لیست `WAN` باشد:

```bash
/interface/list/member/print where list=WAN
```

اگر از لیست اینترفیس `WAN` استفاده نمی‌کنید، کافی است در تنظیمات پنل فیلد **لیست اینترفیس ورودی (In-Interface List)** را خالی بگذارید؛ در این حالت میکروزیا از `dst-address-type=local` استفاده می‌کند.
</Step>

<Step>
### پیکربندی منوی NAT خودکار میکروتیک در پنل

در پنل میکروزیا به مسیر **تنظیمات پنل (Panel Settings) ← NAT خودکار میکروتیک (RouterOS NAT)** بروید و فیلدها را تنظیم کنید:

| فیلد | توضیح | مثال |
| --- | --- | --- |
| **فعال‌سازی مدیریت خودکار NAT** | فعال یا غیرفعال کردن همگام‌سازی خودکار | `روشن` |
| **آدرس IP میکروتیک (API Host)** | آدرس IP خصوصی گیت‌وی/بریج میکروتیک | `172.16.10.1` |
| **پورت API میکروتیک** | پورت سرویس `/ip/service` برای `api` | `8728` |
| **نام کاربری API میکروتیک** | کاربر ساخته‌شده در مرحله ۱ | `mikrozia-nat` |
| **رمز عبور API میکروتیک** | رمز عبور کاربر اختصاصی API | `••••••••` |
| **آدرس IP کانتینر (Target IP)** | آدرس IP خصوصی کانتینر برای `to-addresses` (دکمه **تشخیص خودکار** آن را پر می‌کند) | `172.16.10.2` |
| **لیست اینترفیس ورودی** | نام Interface List ورودی یا خالی برای `dst-address-type=local` | `WAN` |

1. ابتدا روی دکمه **تست اتصال میکروتیک (Test Connection)** کلیک کنید؛ باید نام روتر (Identity)، نسخه RouterOS و تعداد رول‌های NAT نمایش داده شود.
2. کلید **فعال‌سازی مدیریت خودکار NAT در میکروتیک** را روشن کرده و دکمه **ذخیره (Save)** را بزنید.
3. برای ساخت رول NAT برای اینباندهایی که قبلاً ایجاد کرده‌اید، روی **همگام‌سازی همه اینباندها (Sync All Inbounds)** کلیک کنید.
</Step>

</Steps>

## رفتار میکروزیا هنگام مدیریت اینباندها

- **ساخت اینباند جدید**: رول `dst-nat` روی پورت و پروتکل اینباند (`tcp`، `udp` یا هر دو برای پروتکل‌هایی مانند Shadowsocks با `tcp,udp`) ساخته می‌شود.
- **ویرایش اینباند**: اگر پورت یا پروتکل تغییر کند، رول‌های متعلق به آن اینباند به‌روزرسانی و رول‌های قدیمی اضافی آن پاک می‌شوند.
- **غیرفعال کردن اینباند (Disable)**: رول NAT آن در میکروتیک **حذف نمی‌شود**، بلکه روی حالت `disabled=yes` قرار می‌گیرد و با فعال‌سازی مجدد دوباره `disabled=no` می‌شود.
- **حذف اینباند (Delete)**: فقط رول‌های دارای برچسب همان اینباند از میکروتیک حذف می‌شوند.
- **اینباندهای محلی (`127.0.0.1`) و نودهای راه‌دور**: برای اینباندهایی که روی `127.0.0.1` گوش می‌دهند یا متعلق به نودهای راه‌دور هستند، رول NAT ساخته نمی‌شود.

## مشاهده رول‌های تحت مدیریت در میکروتیک

برای دیدن تمام رول‌هایی که میکروزیا ساخته است، در ترمینال میکروتیک اجرا کنید:

```bash
/ip/firewall/nat/print where comment~"^mikrozia:managed:inbound:"
```

## عیب‌یابی رایج

| خطا / وضعیت | علت احتمالی | راه‌حل |
| --- | --- | --- |
| **Connection refused / timeout** | سرویس `api` خاموش است، `address` محدود شده یا فایروال ورودی پورت `8728` را بسته است. | تنظیمات `/ip/service/print` و رول `chain=input` فایروال میکروتیک را بررسی کنید. |
| **Authentication failed** | نام کاربری/رمز اشتباه است یا گروه کاربر سیاست `api` را ندارد. | گروه `mikrozia-nat` را با `policy=read,write,api` بررسی کنید. |
| **NAT conflict detected** | یک رول `dstnat` دستی و فعال روی همان پورت و پروتکل در میکروتیک وجود دارد. | میکروزیا برای حفظ ایمنی رول دستی شما را تغییر نمی‌دهد؛ رول دستی تکراری را در میکروتیک حذف یا غیرفعال کنید و مجدداً ذخیره بزنید. |
| **Invalid host / target IP** | آدرس IP عمومی وارد شده است. | فقط آدرس‌های IP خصوصی (مانند `172.16.10.1` یا `192.168.x.x`) مجاز هستند. |
