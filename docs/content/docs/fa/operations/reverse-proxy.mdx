پراکسی معکوس به شما امکان می‌دهد پنل و اشتراک را روی یک دامنه تمیز با HTTPS خودکار
ارائه دهید و پورت‌های واقعی را پشت پورت‌های 80/443 پنهان کنید. پراکسی بیرون از
کانتینر و معمولاً روی میزبانی دیگر اجرا می‌شود.

<Callout type="info">
  پنل اکنون می‌تواند گواهی خودش را بگیرد: Image یک کلاینت ACME با نسخهٔ Pin‌شده
  دارد، پس می‌توانید با HTTP-01 یا Cloudflare DNS-01 گواهی صادر کنید و خودِ پنل
  HTTPS را ارائه می‌کند. به [گواهی‌های TLS](/docs/config/ssl-certificates)
  مراجعه کنید. میزبان پراکسی اختیاری است — وقتی مفید است که پنل باید روی یک
  آدرس خصوصی بماند، یا وقتی می‌خواهید یک لایهٔ کش و Log در جلوی پنل داشته باشید.
</Callout>

پراکسی باید پنل را در آدرس کانتینر (`172.16.10.2:2053` در چیدمان مبتدی) ببیند.
برقرارکردن این مسیر — از جمله Port Forward یا Routing — سیاست RouterOS است که خودتان
تنظیم می‌کنید و Mikrozia آن را ایجاد نمی‌کند. به
[پورت‌ها و فایروال](/docs/reference/ports-firewall) مراجعه کنید.

## Nginx + گواهی

با Nginx، گواهی را روی میزبان پروکسی (بیرون از کانتینر Mikrozia) با `certbot`
(یا `acme.sh`) دریافت کنید و در بلوک server به آن ارجاع دهید:

```bash title="certbot"
certbot certonly --nginx -d panel.example.com
```

پس از نصب گواهی، Nginx را بارگذاری مجدد کنید و تمدید خودکار را راه‌اندازی کنید
(`certbot renew` به‌صورت پیش‌فرض روی یک تایمر اجرا می‌شود).

## Caddy

Caddy گواهی‌ها را برای شما دریافت و تمدید می‌کند — یک Caddyfile را به پنل اشاره
دهید و همه‌چیز کار می‌کند:

```text title="Caddyfile"
panel.example.com {
    reverse_proxy 172.16.10.2:2053 {
        header_up X-Real-IP {remote_host}
    }
}
```

## نکته‌ها

- حتی پشت یک پراکسی هم **مسیر پایه وب** پنل را حفظ کنید؛ دفاع لایه‌به‌لایه.
- اگر TLS را در پراکسی مدیریت می‌کنید، ممکن است بخواهید `XUI_SKIP_HSTS=true` را روی
  پنل تنظیم کنید — به [مرجع متغیرهای محیطی](/docs/reference/env-vars) مراجعه کنید.
- سرور [اشتراک](/docs/config/subscription) را هم پراکسی کنید تا محتوای آن نیز روی
  HTTPS ارائه شود.

## منسوخ: جریان گواهی Reverse Proxy متعلق به RouterOS

راهنمای پیشین از شما می‌خواست TLS را روی خود RouterOS با گواهی متعلق به RouterOS
(یا اجرای صادرکنندهٔ گواهی روی روتر) پایان دهید و آن گواهی را به داخل کانتینر
درون‌ریزی کنید. این جریان از مستندات جاری منسوخ شده است: گواهی‌ها را کلاینت ACME
پیوست‌شده صادر می‌کند و زیر `/root/cert` نگه می‌دارد، و Mikrozia هرگز کلید خصوصی
RouterOS را به داخل کانتینر نمی‌آورد.

نصب‌هایی که هنوز از جریان قدیمی استفاده می‌کنند دست‌نخورده کار می‌کنند — به‌روزرسانی
Image چیزی را حذف یا بازنویسی نمی‌کند. اگر می‌خواهید به مسیر پشتیبانی‌شده بروید،
گواهی را با کلاینت پیوست‌شده صادر کنید (یا گواهی خودتان را درون‌ریزی کنید) و پنل را
به آن اشاره دهید.
