代理面板是高价值目标。几层加固措施就能带来很大改善。

## 面板加固

- 强而唯一的凭据，并启用**双因素认证**（TOTP）。
- 使用非默认的面板端口，以及一个长且随机的 Web 根路径。
- 为面板启用 TLS（直接启用，或通过[反向代理](/docs/operations/reverse-proxy)）。
- 内置的**登录限制器**会在某个 IP/用户名于 5 分钟内连续 5 次登录失败后将其封锁
  （封锁 15 分钟），并且面板可以将自身的出站流量经由某个 outbound 路由出去。

完整的检查清单请参见[首次登录](/docs/guide/first-login)。

## 客户端 IP 日志

面板通过 Xray 在线统计 API 记录它为每个客户端观察到的源 IP（参见[客户端](/docs/config/clients)）。
这只是观察：RouterOS 容器无法安装或运行 Fail2ban、`iptables` 或 `nftables`，Mikrozia
也绝不会创建或修改 RouterOS 防火墙规则。因此，限制每个客户端同时使用的源 IP 数量
是 RouterOS 管理员的职责。

旧版本存储的 `limitIp` 值会原样保留。面板不会应用这些值，也不会在升级、迁移、
备份或恢复过程中重置、清零或重新解释它们。

## 网络策略

只开放你实际使用的端口：RouterOS 管理、面板端口、订阅端口以及你的入站端口。Mikrozia
没有防火墙菜单，也不附带 `ufw`、`iptables` 或 `nftables`；所有过滤、NAT、端口转发、
路由和访问控制策略均由 RouterOS 管理员配置。参见
[端口与防火墙](/docs/reference/ports-firewall)。

<Callout type="warn">
  在应用限制性策略之前，请确保 RouterOS 管理访问仍然可用。请从第二个会话进行测试，
  以免把自己锁在外面。
</Callout>

## 宿主机内核边界（BBR）

Mikrozia 的 `x-ui` 菜单**不包含**宿主机内核 BBR 或 `sysctl` 开关：

- RouterOS 拥有宿主机内核，容器无法安装内核模块，也无法修改宿主机内核 TCP 拥塞控制算法（`net.ipv4.tcp_congestion_control`、`net.core.default_qdisc`）。
- 在容器内执行 `sysctl` 无法凭空提供内核缺失的功能，RouterOS 的 Queue 或 Firewall 规则也不能替代 Kernel BBR。
- **TUIC**、**QUIC** 与 **FinalMask** 中的用户态 `bbr` 拥塞控制不依赖宿主机内核，已完整保留。
- Xray sockopt 中的 `tcpcongestion=bbr` 属于内核相关选项，目前保留并等待后续独立兼容性审计。

## 保持更新

面板、Xray、sidecar 组件和 Geo 数据都是不可变的镜像内容，容器内没有软件更新器。
安全修复随新的版本化镜像发布：从 Docker Hub `echodev7/mikrozia` 拉取新标签，使用相同的
`/etc/x-ui` 与 `/root/cert` 挂载重新创建容器，并在验证新镜像之前保留旧镜像。参见
[更新与卸载](/docs/guide/update-uninstall)。
