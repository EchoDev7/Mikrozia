TLS 证书让你通过 HTTPS 提供**面板**服务（加密登录和 API 流量），并在**入站**
（VLESS-TLS、Trojan、Shadowsocks-TLS 等）上终止 TLS。Mikrozia 只**读取**你提供
的证书文件，不会在容器内运行 ACME 客户端、certbot 或任何其他证书签发工具。

<Callout type="warn">
  证书的获取和续期由**用户自行管理**。Mikrozia 从不在运行时下载或安装证书工具，
  也从不创建或修改 RouterOS 的防火墙、NAT 或端口转发规则。如果你的验证方式需要
  公网端口，请自行在 RouterOS 中配置相应访问。
</Callout>

## 在容器外获取证书

在你控制的宿主机上，按证书颁发机构提供的签发和续期流程操作，然后把生成的文件
复制到路由器的持久证书存储。不要在 Mikrozia 容器内安装软件包或运行证书安装程序。

证书及其私钥通常是两个文件：

- `fullchain.pem` — 证书及中间证书链。
- `privkey.pem` — 私钥。请妥善保密，切勿放入镜像、支持包或日志。

## 放到持久证书挂载目录

在 `/root/cert`（RouterOS 证书挂载在容器内的路径）下为每份证书创建一个目录：

```text
/root/cert/vpn.example.com/fullchain.pem
/root/cert/vpn.example.com/privkey.pem
```

配置面板前，两个文件都必须已存在于最终路径。该目录是持久挂载，因此证书在替换
容器镜像和回滚后仍会保留。

## 让面板使用这些文件

任选一种等效方式：

- 运行 `x-ui`，选择 **`14` — TLS Certificate Paths**，然后选择 **`2` — Set
  certificate paths for the panel**。
- 或直接运行命令：

  ```bash
  x-ui cert -webCert /root/cert/vpn.example.com/fullchain.pem \
    -webCertKey /root/cert/vpn.example.com/privkey.pem
  x-ui restart
  ```

- 或在[面板设置](/docs/config/panel#tls)中设置 `webCertFile` 和
  `webKeyFile`。

只有**两个**路径都已设置且两个文件都可读时，面板才会切换到 HTTPS。要清除它们，
请运行 `x-ui cert -reset`。

## 在入站中使用证书

为入站启用 TLS 时，在入站的 TLS 设置中引用相同的证书和密钥路径（或粘贴其
内容）。参见[入站](/docs/config/inbounds)和[传输](/docs/config/transports)。
[REALITY](/docs/config/reality) 入站**不需要**证书，它们借用真实站点的 TLS。

## 续期与轮换

续期在容器外按你管理的时间表进行。当证书颁发机构签发新证书后，覆盖相同的
`fullchain.pem` 和 `privkey.pem` 文件，使面板中保存的路径继续有效，然后重载
面板：

```bash
x-ui restart
```

`x-ui restart` 会重载面板的 Web 和订阅服务，并重启运行中容器内的 Xray。容器内
没有续期守护进程或 cron 任务，也不会自动获取任何证书。

如果证书移动到其他路径，请通过菜单 `14` 或 `x-ui cert` 再次更新面板设置。

<Callout type="info">
  证书会过期。请使用外部签发工具监控有效期，并在到期前替换已挂载的文件；面板会
  持续从配置的路径读取文件。
</Callout>
