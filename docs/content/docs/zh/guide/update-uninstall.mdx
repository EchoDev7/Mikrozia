在容器内部或通过终端，`x-ui` 命令是你的管理中心。不带参数运行它会打开交互式菜单，
或传入一个子命令来直接执行单次操作。

```bash
x-ui
```

## `x-ui` 管理菜单

菜单（选项 `0`–`16`）在顶部显示面板和 Xray 状态：

| #     | 选项                                   | 功能说明                                                  |
| ----- | -------------------------------------- | --------------------------------------------------------- |
| 1     | Environment-Managed Admin Credentials  | 显示凭据来源以及在 RouterOS 中设置它的命令                   |
| 2     | Reset Web Base Path                    | 重置 Web 根路径                                           |
| 3     | Reset Settings                         | 重置面板设置（保留用户与数据）                               |
| 4     | Change Port                            | 修改面板端口                                               |
| 5     | View Current Settings                  | 显示用户名、端口、Web 根路径及证书路径                       |
| 6–7   | Show RouterOS Start / Stop Command     | 显示 RouterOS `/container/start` 与 `/container/stop` 命令 |
| 8     | Reload Panel & Restart Xray            | 在容器内重载面板 Web/订阅服务（`SIGHUP`）并重启 Xray（`SIGUSR1`），不重启容器本身 |
| 9     | Restart Xray Only                      | 发送 `SIGUSR1` 仅在容器内重启 Xray-core 核心                 |
| 10    | Check Status                           | 查看面板、Xray 和 MTProto 运行状态及 RouterOS 自启检查命令   |
| 11    | Logs Management                        | 查看面板调试日志 / RouterOS 容器日志命令                     |
| 12–13 | Show RouterOS Enable / Disable Autostart Command | 显示 RouterOS `/container/set` 自启与重启策略命令          |
| 14    | TLS Certificates                       | 使用内置 ACME 客户端签发、导入并查看证书                     |
| 15    | RouterOS Network Policy Notice         | RouterOS 网络策略与防火墙配置说明                           |
| 16    | Database Tools                         | SQLite `.db` ↔ `.dump` 转换与外部 PostgreSQL 指南         |
| 0     | Exit                                   | 退出脚本                                                   |

其中部分功能有各自的详细指南：[TLS 证书](/docs/config/ssl-certificates)
（选项 14）、[面板设置](/docs/config/panel)（TLS），以及 [数据库](/docs/reference/database)（PostgreSQL）。

## 命令行子命令

对于自动化脚本和快速运维，`x-ui` 支持直接执行子命令：

| 子命令                     | 操作说明                                            |
| -------------------------- | --------------------------------------------------- |
| `x-ui version`             | 显示当前 Mikrozia 版本                              |
| `x-ui start` / `stop`      | 显示 RouterOS `/container/start` 与 `/container/stop` 命令（由 RouterOS 控制） |
| `x-ui restart`             | 在运行中的容器内重载面板并重启 Xray（不会重启 RouterOS 容器本身） |
| `x-ui restart-xray`        | 仅在运行中的容器内重启 Xray 核心（`SIGUSR1`）       |
| `x-ui status`              | 显示面板/Xray/MTProto 状态及 RouterOS 自启检查命令  |
| `x-ui settings`            | 显示当前配置                                        |
| `x-ui enable` / `disable`  | 显示 RouterOS `/container/set` 的 `start-on-boot` 与 `restart-policy` 命令 |
| `x-ui log`                 | 查看实时调试日志                                    |
| `x-ui migrateDB [file]`    | 转换 SQLite 数据库（.db 与 .dump 之间互转）         |
| `x-ui acme <command>`     | `status`、`check`、`issue`、`renew`、`cloudflare setup` —— 证书 |

## 更新

在 Mikrozia 架构中，面板更新完全通过替换容器或容器镜像实现。原版 3x-ui 在容器内部通过脚本执行自更新（`update.sh`）的危险路径已被彻底移除，以保护容器 RootFS 结构并确保 RouterOS 环境的长期稳定性。

更新步骤：
1. 拉取新的 Mikrozia 容器镜像标签（例如 Docker Hub 上的 `echodev7/mikrozia`）。
2. 停止当前容器并使用新镜像重新创建，同时挂载原有的持久化目录（`/etc/x-ui` 和 `/root/cert`）。
3. 启动新容器。

持久化目录中的数据库、用户凭据和证书将在容器重建过程中完全保留。在进行跨大版本更新前，请务必先创建[备份](/docs/operations/backup-restore)。

### 回滚镜像更新

如果新镜像未通过验证，请保持容器停止，使用之前的版本化镜像标签重新创建容器，并继续使用相同的 `/etc/x-ui` 和 `/root/cert` 挂载。数据库和证书不属于镜像内容。如果新镜像已经迁移了数据库架构，请先恢复更新前的数据库备份，再启动旧镜像；旧面板绝不能打开更新版本的架构。镜像回滚不需要将任何数据复制到镜像 RootFS。

<Callout type="info">
  Mikrozia 容器在运行时绝不会擅自修改自身的根文件系统。通过镜像替换部署，可确保环境干净、不可变且高度可复现。
</Callout>

如需从 RouterOS Terminal 或 WinBox 完整重启容器，请运行：`/container/restart [find where comment="[Mikrozia:container] Container"]`。

## 卸载

在 RouterOS 中卸载 Mikrozia：
1. 停止容器：`/container/stop [find where comment="[Mikrozia:container] Container"]`
2. 移除容器实例：`/container/remove [find where comment="[Mikrozia:container] Container"]`

<Callout type="warn">
  在 RouterOS 中删除容器不会自动删除宿主机上的持久化挂载目录（`/etc/x-ui` 与 `/root/cert`）。清除持久化数据与证书必须由管理员在宿主机存储上手动且明确地执行，以避免任何意外数据丢失。
</Callout>
