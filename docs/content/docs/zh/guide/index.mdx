**Mikrozia** 是面向 [Xray-core](https://github.com/XTLS/Xray-core) 的 Web 控制面板，
以不可变的 MikroTik RouterOS 容器镜像形式交付。你无需手写并重载 Xray 的 JSON
配置，而是通过浏览器仪表盘管理一切——入站、协议、客户端、证书与订阅。

## 组件如何协作

<Mermaid
  chart={`
flowchart LR
  Admin["管理员浏览器"] -->|面板端口| ROS["RouterOS 网络策略（由用户管理）"]
  ROS -->|容器地址| Panel["Mikrozia 面板（容器）"]
  Panel -->|写入配置并重载| Xray["Xray-core（同一镜像）"]
  Panel --- DB[("SQLite 或外部 PostgreSQL")]
  Clients["客户端应用"] -->|VLESS / VMess / Trojan / ...| ROS
  Xray -->|代理流量| Internet["互联网"]
`}
/>

- **面板**是管理层：把配置保存到数据库、渲染仪表盘、提供 REST API，并写入
  运行中的 Xray 配置。
- **Xray-core** 是数据层：在你的**入站**上接受客户端连接，并将流量转发到目标。
- **客户端应用**（如 v2rayNG、Clash/Mihomo、Hiddify 等）使用面板为每个客户端
  生成的分享链接或订阅进行连接。
- **RouterOS** 负责容器运行时、网络路径以及全部防火墙、NAT 和路由策略。

## 你能获得什么

- 覆盖所有主流协议的**入站**仪表盘——VLESS、VMess、Trojan、Shadowsocks、
  WireGuard、AmneziaWG（用户态）、TUIC v5、Hysteria2、SOCKS、HTTP 和
  Dokodemo-door。
- 对 **REALITY** 与 **XTLS-Vision** 的一流支持，实现隐蔽且快速的传输。
- **按客户端**的流量配额、到期时间、IP 记录、在线状态以及一键分享链接/二维码。
- **订阅**支持 VLESS、Clash/Mihomo 与 JSON 格式。
- 运维工具：**多节点**管理、**Telegram 与 Discord 机器人**、备份以及有文档的
  REST API。

## 它不是什么

- 不是 Linux VPS 或 systemd 服务；没有主机安装程序、发行版软件包、tarball、
  Windows 构建或 Docker Compose 生产路径。
- 不是防火墙、NAT、端口转发或访问控制管理器。
- 内置 ACME 客户端支持手动续期的 HTTP-01 和自动续期的 Cloudflare DNS-01；
  证书与续期状态持久保存在 `/root/cert`。
- 不会自我更新：面板、Xray、sidecar 组件与 Geo 数据只能通过替换镜像更新。

## 内部实现

| 层       | 技术 |
| -------- | ---- |
| 平台     | MikroTik RouterOS 容器（参考平台 CHR x86_64） |
| 后端     | Go 与 Gin Web 框架 |
| 前端     | TypeScript / React |
| 数据库   | `/etc/x-ui` 上的 SQLite（默认）或外部 PostgreSQL |
| 代理引擎 | Xray-core（随镜像内置） |

默认 SQLite 数据库位于 `/etc/x-ui/x-ui.db`，面板在容器内监听端口 **2053**。
两者均可配置——参见[首次登录](/docs/guide/first-login)与环境变量参考。

## 适用人群

Mikrozia 面向希望拥有 Xray 面板、又不想放弃 RouterOS 对网络控制权的 RouterOS
运维人员。如果你需要 systemd 的 VPS 安装，请使用上游
[3x-ui](https://github.com/MHSanaei/3x-ui)。
