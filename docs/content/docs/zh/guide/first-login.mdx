安装完成后，你的第一项任务就是登录并**保护好面板**，然后再对外暴露其他任何内容。

## 进入面板

面板在容器内监听：

```text
http://172.16.10.2:2053/<web-base-path>
```

从你的管理网络访问该地址属于 RouterOS 网络设计；参见
[端口与防火墙](/docs/reference/ports-firewall)。默认面板端口为 **2053**，默认
根路径为 `/`。

### 找到你的登录凭据

管理员凭据就是你在容器环境中设置的那些 —— 没有生成的首次登录密码：

```text
/container/envs/print where list=MIKROZIA_ENV
```

请使用[安装](/docs/guide/installation)时设置的 `MIKROZIA_ADMIN_USERNAME` 与
`MIKROZIA_ADMIN_PASSWORD`。面板每次启动都会用这两个值对齐已保存的账号，因此它们
是唯一的可信来源。在容器内，`x-ui settings` 会显示当前设置。

<Callout type="warn">
  RouterOS 的容器环境是配置存储，而不是机密存储：`/container/envs` 中的每个值
  对任何能读取或导出路由器配置的人都可见。请使用强而唯一的管理员密码，并在该
  配置可能泄露时在环境中修改它并重启容器。
</Callout>

## 修改凭据、端口和路径

使用非默认端口和一个长而随机的 **Web 根路径**，能让面板更难被发现。你可以在 UI 的**面板设置**中修改，或通过 `x-ui` 菜单修改：

- **1 — Reset Username & Password**（可同时禁用 2FA）
- **2 — Reset Web Base Path**（将其随机化）
- **4 — Change Port**

修改用户名或密码会**注销所有现有会话**；如果当时启用了双因素认证，还会将其禁用。

<Callout type="info">
  当容器环境拥有管理员账号时，无法在面板中或通过 `x-ui setting -username … -password …`
  修改用户名和密码：面板会直接说明原因，而不是接受一个下次启动就会被覆盖的值。
  请改为在 RouterOS 中修改 `MIKROZIA_ADMIN_USERNAME` 与
  `MIKROZIA_ADMIN_PASSWORD`，然后重启容器。
</Callout>

## 双因素认证（2FA）

基于 3x-ui 的面板支持 TOTP 双因素认证（兼容 Google Authenticator、Aegis 等）。在**面板设置**中启用即可——启用后，登录页面除了密码外还会要求输入一个 6 位验证码，并且开启该功能会强制所有人重新登录。你可以通过菜单的 **Reset Username & Password** 步骤，或使用 `x-ui setting -resetTwoFactor` 来禁用它。

## 内置登录保护

- **暴力破解限制：** 同一 IP/用户名在 5 分钟内登录失败 **5** 次后，该组合将被封锁 **15 分钟**。
- **通用错误提示：** 无论是凭据错误还是 2FA 验证码错误，登录页面都只提示 "wrong username or password"，因此不会泄露任何信息。
- **会话**有效期为 `sessionMaxAge` 分钟（默认 **360** = 6 小时），并在你修改凭据时失效。
- 可在面板设置中启用 **LDAP** 作为认证回退方案。

## 必备加固清单

<Steps>

<Step>
### 设置高强度且唯一的凭据

在首次启动前，于容器环境中为管理员选择高强度且唯一的密码，并避免它出现在共享
的配置导出中。
</Step>

<Step>
### 使用非默认端口和随机根路径

将面板从 `2053` 端口移走，并将其置于一个长而随机的路径下提供服务。
</Step>

<Step>
### 启用双因素认证

开启 2FA，这样即便密码泄露，单凭密码也无法获得访问权限。
</Step>

<Step>
### 将面板置于 TLS 之后

使用镜像内置的 ACME 客户端签发证书（菜单 `14 — TLS Certificates`，或
`x-ui acme issue --http …` / `x-ui acme issue --dns …`）—— 证书会安装在
`/root/cert` 挂载上，面板路径也会自动更新 —— 或用 `x-ui cert` 导入已有证书。
也可以在[反向代理](/docs/operations/reverse-proxy)处终止 TLS。
</Step>

<Step>
### 在 RouterOS 中限制访问

只开放你确实需要的端口，并使用 RouterOS 防火墙和路由策略限制可以访问面板的人。
Mikrozia 不创建这些规则。
</Step>

</Steps>

<Callout type="info">
  想让面板运行在一个干净的域名上并自动启用 HTTPS？请参阅
  [反向代理](/docs/operations/reverse-proxy)。如需更深入的加固，请参阅
  [安全](/docs/operations/security)。
</Callout>
