Mikrozia 只在容器**内部**监听少量端口。它从不创建或修改 RouterOS 的
firewall、NAT、masquerade、端口转发、路由或访问控制规则，镜像中也不包含
`ufw`、`iptables` 或 `nftables`。

## 容器内部端口

| 端口（默认） | 用途 |
| ------------ | ---- |
| `2053` | 面板（可在 Panel Settings 中修改） |
| `2096` | 订阅服务器（如已启用） |
| inbound 端口 | 你为每个 Xray inbound 指定的端口 |

入门布局中的容器地址为 `172.16.10.2`。

## 网络策略由你决定

在 RouterOS 中决定这些端口如何被访问：

- 哪个接口或地址列表可以访问面板；
- 是否以及如何将 inbound 端口转发到 `172.16.10.2`；
- 容器如何访问互联网；
- drop、限速和日志策略。

Mikrozia 会记录所需端口，但不会自动执行这些步骤。请遵循 MikroTik 的 RouterOS
文档配置 firewall、NAT 和路由。

<Callout type="warn">
  应用任何限制性策略前，请确保对 RouterOS 本身的管理访问仍然可用。请从第二个
  会话进行测试，以免把自己锁在外面。
</Callout>

## 从内部检查

如果客户端无法连接，先确认面板和 Xray 在容器内运行：

```text
/container/print detail where comment="[Mikrozia:container] Container"
/log/print follow-only where topics~"container"
```

然后确认你的 RouterOS 策略确实将流量送达容器地址和端口。参见
[故障排查](/docs/help/troubleshooting)。
