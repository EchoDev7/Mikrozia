Mikrozia is installed **only as a RouterOS Container**. The supported platform is
MikroTik RouterOS `7.25+` with the matching Container package; CHR x86_64 is the
reference environment for this beginner path. Mikrozia is not installed on a
Linux VPS, with systemd, from a tarball or release archive, on Windows, or as a
Docker Compose production stack.

<Callout type="warn">
  Mikrozia never creates or changes RouterOS firewall, NAT, port-forwarding,
  routing-policy, address-list, or access-control rules. Those decisions belong
  to the RouterOS administrator. Mikrozia only documents the ports it listens on
  inside the container.
</Callout>

## Requirements

| Resource | Minimum | Recommended |
| -------- | ------: | ----------: |
| RouterOS | `7.25.0` stable | latest stable |
| Container package | exactly the RouterOS version | exactly the RouterOS version |
| RAM | 2 GiB | 4 GiB |
| Free storage | 2 GiB | 8 GiB or more |
| Architecture | `linux/amd64` (CHR) | published `amd64`, `arm64/v8`, `arm/v7` |

Check the current state before you start:

```text
/system/resource/print
/system/package/print
/disk/print
```

## Back up RouterOS first

```text
/system/backup/save name=before-mikrozia password="a-strong-password"
/export hide-sensitive file=before-mikrozia
```

Download both files with WinBox before changing anything.

## Enable container support

1. Upgrade RouterOS from the `stable` channel.
2. Download the **Extra packages** archive for the same RouterOS version and
   x86 architecture from MikroTik.
3. Upload `container-<version>-x86.npk` with WinBox and reboot.
4. Confirm the package is present and its version matches RouterOS exactly:

```text
/system/package/print where name="container"
```

5. Enable container support in Device Mode:

```text
/system/device-mode/update container=yes
```

On CHR, power the VM off and on again from the hypervisor (a soft reboot is not
enough). Verify:

```text
/system/device-mode/print
```

`container` must be `yes`.

## Check for address conflicts

The beginner path uses `172.16.10.0/24`:

```text
172.16.10.1  RouterOS bridge
172.16.10.2  Mikrozia container
```

If that subnet, bridge name, or VETH name is already in use, do not reuse it.
Choose free values and apply them consistently to every command below.

```text
/ip/address/print
/ip/route/print
/interface/bridge/print
/interface/veth/print
```

## Install the versioned image

Mikrozia is published as a multi-architecture OCI image on Docker Hub. Use a
versioned tag for production; `latest` is a convenience alias only:

```text
majlot/mikrozia:v1-mikrozia
```

<Callout type="warn">
  These instructions follow the current RouterOS `7.25` container contract.
  Clean-CHR acceptance for P1-CHR-01 has not been completed yet, so validate the
  complete flow on a disposable CHR before production. No real-CHR acceptance is
  claimed here.
</Callout>

Run these commands in order from the RouterOS Terminal or WinBox. They create
only Mikrozia-owned objects, marked with `[Mikrozia:container]`.

### 1. Create persistent directories

`data` becomes `/etc/x-ui`, `cert` becomes `/root/cert`, and `tmp` holds
extraction scratch space. RouterOS creates the versioned root directory during
extraction. If a directory already exists, skip its `/file/add` line.

```text
/file/add name=containers type=directory
/file/add name=containers/mikrozia type=directory
/file/add name=containers/mikrozia/data type=directory
/file/add name=containers/mikrozia/cert type=directory
/file/add name=containers/mikrozia/tmp type=directory
```

### 2. Create the bridge and VETH

```text
/interface/bridge/add name=br-mikrozia comment="[Mikrozia:container] Bridge"
/ip/address/add address=172.16.10.1/24 interface=br-mikrozia comment="[Mikrozia:container] Gateway"
/interface/veth/add name=veth-mikrozia address=172.16.10.2/24 gateway=172.16.10.1 comment="[Mikrozia:container] VETH"
/interface/bridge/port/add bridge=br-mikrozia interface=veth-mikrozia comment="[Mikrozia:container] Bridge Port"
```

### 3. Add mounts and environment variables

```text
/container/mounts/add list=MIKROZIA_DATA src=containers/mikrozia/data dst="/etc/x-ui" comment="[Mikrozia:container] Data Mount"
/container/mounts/add list=MIKROZIA_CERT src=containers/mikrozia/cert dst="/root/cert" comment="[Mikrozia:container] Cert Mount"
/container/envs/add list=MIKROZIA_ENV key=XUI_PORT value="2053" comment="[Mikrozia:container] Environment"
/container/envs/add list=MIKROZIA_ENV key=HOME value="/root" comment="[Mikrozia:container] Environment"
```

### 4. Configure the registry and add the container

`/container/config/set` only changes the registry and extraction directory. The
versioned tag is pinned in `/container/add`; `memory-high`, `memory-max`, and
`start-on-boot` match the runtime contract.

```text
/container/config/set registry-url="https://registry-1.docker.io" tmpdir=containers/mikrozia/tmp
/container/add remote-image="majlot/mikrozia:v1-mikrozia" interface=veth-mikrozia root-dir=containers/mikrozia/root-v1-mikrozia mountlists="MIKROZIA_DATA,MIKROZIA_CERT" envlist=MIKROZIA_ENV dns="1.1.1.1,8.8.8.8" memory-high=512M memory-max=1024M logging=yes start-on-boot=yes comment="[Mikrozia:container] Container"
```

These commands do not add firewall, NAT, masquerade, port-forwarding, or routing
rules. Outbound connectivity and panel reachability remain RouterOS
administrator decisions.

## Wait for extraction and start

```text
/container/print detail
/log/print follow-only where topics~"container"
```

Extraction can take several minutes. Do not remove the container or power off
CHR until it finishes. Then start it:

```text
/container/start [find where comment="[Mikrozia:container] Container"]
/container/print detail where comment="[Mikrozia:container] Container"
```

The state must be `running`.

## Reach the panel

The panel listens on `2053/TCP` **inside** the container (`172.16.10.2`). How
that port becomes reachable from your management network is your RouterOS
network design; Mikrozia does not publish or forward it for you. See
[Ports & firewall](/docs/reference/ports-firewall).

## Initial credentials

On first boot the panel generates a random username and password and prints them
once to the container log:

```text
/log/print where topics~"container"
```

Look for `Username:` and `Password:`. If the log is gone, open a container
shell and reset them:

```text
/container/shell [find where comment="[Mikrozia:container] Container"]
```

```sh
/app/x-ui setting -username NEW_USER -password 'NEW_STRONG_PASSWORD'
exit
```

Then continue to [First login](/docs/guide/first-login).

## Database

SQLite is the default and stores a single file at `/etc/x-ui/x-ui.db`, on the
persistent mount. External PostgreSQL is optional and is configured through
RouterOS `/container/envs` (`XUI_DB_TYPE=postgres` and `XUI_DB_DSN`); Mikrozia
never installs a database server inside the container. See
[Database](/docs/reference/database).

## Customizing the values

If the default names, subnet, or storage location conflict with your RouterOS
setup, change them consistently in every command above: the bridge, VETH, IP
addresses, directories, mount sources, and `mountlists`. Keep the same
`[Mikrozia:container]` comments so the lifecycle and teardown commands can find
the owned objects. Do not adopt a conflicting subnet or rename an existing
RouterOS object.
