After installation, your first job is to log in and **secure the panel** before
exposing anything else.

## Reach the panel

The panel listens inside the container:

```text
http://172.16.10.2:2053/<web-base-path>
```

Reaching that address from your management network is your RouterOS network
design; see [Ports & firewall](/docs/reference/ports-firewall). The default panel
port is **2053** and the default base path is `/`.

### Find your credentials

The administrator credential is the one you set in the container environment —
there is no generated first-login password:

```text
/container/envs/print where list=MIKROZIA_ENV
```

Use the `MIKROZIA_ADMIN_USERNAME` and `MIKROZIA_ADMIN_PASSWORD` values you
configured during [installation](/docs/guide/installation). The panel
reconciles the stored account with them on every start, so both values are the
single source of truth. Inside the container, `x-ui settings` shows the current
settings.

<Callout type="warn">
  The RouterOS Container Environment is a configuration store, not a secret
  store: every value in `/container/envs` is visible to anyone who can read or
  export the router configuration. Use a strong, unique administrator password
  and change it in the environment (then restart the container) whenever that
  configuration could have been exposed.
</Callout>

## Change credentials, port, and path

A non-default port and a long, random **web base path** make the panel much
harder to find. Change them from **Panel Settings** in the UI, or from the
`x-ui` menu:

- **1 — Reset Username & Password** (optionally disabling 2FA at the same time)
- **2 — Reset Web Base Path** (randomizes it)
- **4 — Change Port**

Changing your username or password **logs out all existing sessions** and, if
two-factor auth was on, disables it.

<Callout type="info">
  When the container environment owns the administrator account, the username and
  password cannot be changed from the panel or from `x-ui setting -username …
  -password …`: the panel says so plainly instead of accepting a value that the
  next start would overwrite. Change `MIKROZIA_ADMIN_USERNAME` and
  `MIKROZIA_ADMIN_PASSWORD` in RouterOS and restart the container instead.
</Callout>

## Two-factor authentication (2FA)

3x-ui-derived panel supports TOTP two-factor auth (compatible with Google
Authenticator, Aegis, etc.). Enable it in **Panel Settings** — once enabled, the login page asks for a
6-digit code in addition to your password, and turning it on forces everyone to
log in again. You can disable it from the menu's **Reset Username & Password**
step or with `x-ui setting -resetTwoFactor`.

## Built-in login protection

- **Brute-force limiter:** after **5** failed logins from the same IP/username
  within 5 minutes, that combination is blocked for **15 minutes**.
- **Generic errors:** the login page reports "wrong username or password" for
  both bad credentials and bad 2FA codes, so it leaks nothing.
- **Sessions** last `sessionMaxAge` minutes (default **360** = 6 hours) and are
  invalidated when you change credentials.
- **LDAP** can be enabled as an auth fallback in Panel Settings.

## Essential hardening checklist

<Steps>

<Step>
### Set strong, unique credentials

Choose a strong, unique administrator password in the container environment
before the first start, and keep it out of shared configuration exports.
</Step>

<Step>
### Use a non-default port and random base path

Move the panel off `2053` and serve it under a long random path.
</Step>

<Step>
### Enable two-factor authentication

Turn on 2FA so a leaked password alone can't grant access.
</Step>

<Step>
### Put the panel behind TLS

Issue a certificate with the bundled ACME client (menu `14 — TLS Certificates`,
or `x-ui acme issue --http …` / `x-ui acme issue --dns …`) — it is installed on
the `/root/cert` mount and the panel paths are updated for you — or import an
existing certificate with `x-ui cert`. Alternatively, terminate TLS at a
[reverse proxy](/docs/operations/reverse-proxy).
</Step>

<Step>
### Restrict access in RouterOS

Open only the ports you actually need, and limit who can reach the panel with
RouterOS firewall and routing policy. Mikrozia does not create those rules.
</Step>

</Steps>

<Callout type="info">
  Want the panel on a clean domain with automatic HTTPS? See
  [Reverse proxy](/docs/operations/reverse-proxy). For deeper hardening, see
  [Security](/docs/operations/security).
</Callout>
