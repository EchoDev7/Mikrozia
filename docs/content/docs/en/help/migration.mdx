## Between RouterOS devices

Moving to another RouterOS device is a mounted-data move:

<Steps>

<Step>
### Back up the old device

Stop the container, then copy the `/etc/x-ui` and `/root/cert` mount contents.
See [Backup & restore](/docs/operations/backup-restore).
</Step>

<Step>
### Install the same Mikrozia tag on the new device

Follow the [RouterOS installation path](/docs/guide/installation) and use the
same image tag unless you are deliberately upgrading. Create the same persistent
mounts.
</Step>

<Step>
### Restore the mounted data

Place the database and certificates on the new persistent mounts before starting
the container. Update any IP- or domain-specific panel settings after it starts.
</Step>

</Steps>

## Between Mikrozia versions

Replacing the container image is the only supported upgrade mechanism. The panel
migrates its own database at startup. Take a [backup](/docs/operations/backup-restore)
first, recreate the container with the new versioned tag and the same
`/etc/x-ui` and `/root/cert` mounts, and keep the previous image until the new
one is verified. Never rewrite the image RootFS from inside the container.

## From x-ui

Importing an older x-ui panel's database directly into Mikrozia is **not
supported** — the schemas differ. Install Mikrozia fresh and recreate
inbounds/clients, exporting share links from the old panel as you go.

<Callout type="warn">
  Always take a backup before any migration, and keep the old server running
  until you've verified the new one.
</Callout>
