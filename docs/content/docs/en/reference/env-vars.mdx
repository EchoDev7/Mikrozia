Mikrozia reads its runtime configuration from environment variables. On
RouterOS Container, define them in `/container/envs` and attach the `envlist` to
your container; for local development with Docker, set them in
`docker-compose.yml` or `docker run -e`. To apply environment changes, recreate
the container with the same persistent mounts (`/etc/x-ui` and `/root/cert`).

## Administrator credentials

The container environment is the **authoritative source** of the panel
administrator account. There is no fixed `admin/admin` default and no generated
first-login password.

| Variable                  | Default | Description                                                       |
| ------------------------- | ------- | ----------------------------------------------------------------- |
| `MIKROZIA_ADMIN_USERNAME` | —       | Administrator username. Must be set together with the password.   |
| `MIKROZIA_ADMIN_PASSWORD` | —       | Administrator password. Must be set together with the username.   |

On every start the panel reconciles the stored administrator account with these
two values: the username and password are updated to match, and a changed
password invalidates the sessions that were issued with the old one. Existing
accounts are never silently deleted or reset.

| Situation                                              | Behavior                                                                                          |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| Both values set                                        | The environment owns the account; the stored account is reconciled on every start.                  |
| Only one of the two set                                | The panel refuses to start and names the missing value. Nothing is changed.                         |
| Neither set, an account already exists                 | The stored account is preserved unchanged and the panel logs that it is managed elsewhere.          |
| Neither set, no account exists                         | The panel refuses to start and asks for both values.                                                |
| Neither set, the stored account still holds the legacy `admin` / `admin` pair | The panel refuses to start and keeps the stored account.                          |

When the environment owns the account, the panel's **Security** tab shows a
notice instead of a password form, and a panel-side password change is refused
with a truthful message — the environment would overwrite it on the next start.

## RouterOS API status and telemetry

The dashboard can perform a read-only native RouterOS API query over the
internal Container-to-router network on TCP/8728 only. These values are
optional; set all three or leave all three unset. Partial configuration is
reported as invalid. Mikrozia does not enable the API service, create users, or
change router settings.

| Variable | Default | Description |
| --- | --- | --- |
| `MIKROZIA_ROUTEROS_API_HOST` | — | Literal private IPv4/IPv6 address of the RouterOS API endpoint (no hostnames, zones, loopback, or link-local addresses). |
| `MIKROZIA_ROUTEROS_API_USERNAME` | — | Dedicated read-only RouterOS API account name (`read,api` policies only). |
| `MIKROZIA_ROUTEROS_API_PASSWORD` | — | RouterOS API account password. |
| `MIKROZIA_ROUTEROS_CONTAINER_COMMENT` | — | Exact unique comment of the Mikrozia RouterOS container; enables read-only Container Log lookup. |
| `MIKROZIA_ROS_CONTAINER_COMMENT` | — | RouterOS Container alias for `MIKROZIA_ROUTEROS_CONTAINER_COMMENT`. Use this shorter name on RouterOS 7.25.1, which does not pass the longer name to the container process. |
| `MIKROZIA_ROUTEROS_RESTART_USERNAME` | — | Separate operational RouterOS API username for the optional Restart Container command. Requires RouterOS read, write, and api policies; keep access on the internal container IP only. |
| `MIKROZIA_ROUTEROS_RESTART_PASSWORD` | — | Password for the separate optional operational account. Never reuse the read-only account. |
| `MIKROZIA_ROS_RESTART_USERNAME` / `MIKROZIA_ROS_RESTART_PASSWORD` | — | RouterOS Container aliases for the two Restart Container credentials. Use this shorter pair on RouterOS 7.25.1. |

Example values are placeholders only:

```text
MIKROZIA_ROUTEROS_API_HOST=172.16.10.1
MIKROZIA_ROUTEROS_API_USERNAME=<READ_ONLY_API_USER>
MIKROZIA_ROUTEROS_API_PASSWORD=<SET_A_SECRET_VALUE>
```

The password is held only in process memory while probing; it is never stored in
the database or returned by the panel API. RouterOS Container `/container/envs`
is visible to router administrators and is not a secret store. Restrict access
to the router configuration. The integration polls `/system/resource/print`
(`uptime`, `cpu-load`, `cpu-count`, `cpu-frequency`, `total-memory`,
`free-memory`) every 15s with a 4s timeout and 30s stale threshold; RouterOS-side
VETH telemetry remains deferred. Container log reads use the dedicated read-only
RouterOS API account together with the exact unique container comment, while
optional Restart Container requires a separate operational RouterOS API account.

When both canonical and short `MIKROZIA_ROS_*` alias variables are available,
the canonical name takes precedence and the short alias is fallback only. After
changing `/container/envs` in RouterOS, restart the container to apply the
updated environment.

## Container network metrics

| Variable | Default | Description |
| --- | --- | --- |
| `MIKROZIA_CONTAINER_INTERFACE` | — | Exact interface name used for Dashboard Overall Speed when automatic collection finds no usable interface. Allowed pattern: `^[A-Za-z0-9._-]{1,63}$`; `lo` and `lo0` are rejected. |

When set, Mikrozia reads only that interface from its own container network
namespace (`/proc/net/dev`). It never queries RouterOS interface counters. A
missing or invalid name leaves Overall Speed unavailable, with no fallback to
another interface. Upload is TX and Download is RX. On hosts where automatic
collection already finds a usable NIC, this variable has no effect.

<Callout type="warn">
  **The RouterOS Container Environment is a configuration store, not a secret
  store.** Every value in `/container/envs` is visible to anyone who can read the
  router configuration or export it. Choose a strong administrator password, and
  protect the router's own access and backups. Mikrozia never prints these
  values to logs, never returns them through an API, and never writes them into
  the image.
</Callout>

## Database

| Variable                 | Default     | Description                                                          |
| ------------------------ | ----------- | -------------------------------------------------------------------- |
| `XUI_DB_TYPE`            | `sqlite`    | Backend: `sqlite`, or `postgres` (also accepts `postgresql` / `pg`). |
| `XUI_DB_FOLDER`          | `/etc/x-ui` | Folder for the SQLite database file (`x-ui.db`).                     |
| `XUI_DB_DSN`             | —           | PostgreSQL URI (`postgres://`/`postgresql://`) or keyword/value DSN (advanced; when `XUI_DB_TYPE=postgres`). Place TLS certs under `/root/cert` (`sslmode=verify-full` recommended); `PGPASSWORD` is not supported. |
| `XUI_DB_MAX_OPEN_CONNS`  | —           | Max open connections in the PostgreSQL pool.                         |
| `XUI_DB_MAX_IDLE_CONNS`  | —           | Max idle connections in the PostgreSQL pool.                         |

The default SQLite database path is `/etc/x-ui/x-ui.db`. See
[Database](/docs/reference/database) for the SQLite ↔ PostgreSQL details.

## Node token encryption

Node API bearer tokens — and the stored PIA token — are kept in plaintext by
default. Encryption at rest is opt-in and fails closed: with any mode other than
`off`, the panel refuses to start unless it can load a key.

| Variable                  | Default                         | Description                                                                                                                                                            |
| ------------------------- | ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `NODE_TOKEN_ENCRYPTION`   | `off`                           | `off`, `migration` (reads accept plaintext or ciphertext, writes encrypt), or `required` (same writes, startup fails without a key). Note the missing `XUI_` prefix.    |
| `XUI_NODE_TOKEN_KEY_FILE` | `/etc/x-ui/node_token_key.json` | JSON keyring, mode `0600` or stricter. Loaded first.                                                                                                                   |
| `XUI_NODE_TOKEN_KEY`      | —                               | A single base64 32-byte key, read only when the key file fails to load. Its key id is fixed to `env`, so it cannot rotate.                                              |

The key file names the active key plus every older key still needed to decrypt:

```json
{ "active": "k1", "keys": { "k1": "<base64 32-byte key>" } }
```

Generate a key with `openssl rand -base64 32`; keys are never accepted as
command-line arguments. After enabling a mode, re-encrypt the rows already in
the database under the active key:

```bash
x-ui encrypt-tokens
```

That covers node rows; the PIA token is re-encrypted the next time it is read.
To rotate, add the new key to `keys`, point `active` at it, keep the old key for
decryption, and run `x-ui encrypt-tokens` again.

## Memory & profiling

The panel keeps memory low via `GOGC` and periodic releases. These are advanced
knobs — leave them unset unless you're tuning a constrained host.

| Variable                      | Default | Description                                                       |
| ----------------------------- | ------- | ----------------------------------------------------------------- |
| `XUI_GOGC`                    | —       | Go GC target percentage; lower = less RAM, slightly more CPU.     |
| `XUI_MEMORY_RELEASE_INTERVAL` | —       | Minutes between `FreeOSMemory` calls; `0` disables.               |
| `XUI_MEMORY_LIMIT`            | —       | Go soft memory limit in **MiB**.                                  |
| `GOMEMLIMIT`                  | —       | Go-syntax soft limit (e.g. `400MiB`); takes precedence over above.|
| `XUI_PPROF`                   | `false` | Expose pprof profiling on `127.0.0.1:6060`.                       |

## Tunnel health monitor

Optional watchdog: it probes a URL (optionally **through** a local Xray inbound)
and restarts Xray after repeated failures. A restart drops all connected
clients, so enable it deliberately.

| Variable                      | Default                                      | Description                                                       |
| ----------------------------- | -------------------------------------------- | ----------------------------------------------------------------- |
| `XUI_TUNNEL_HEALTH_MONITOR`   | `false`                                      | Enable the monitor.                                               |
| `XUI_TUNNEL_HEALTH_PROXY`     | —                                            | Proxy to send the probe through, e.g. `socks5://127.0.0.1:1080`. Empty = only checks host connectivity. |
| `XUI_TUNNEL_HEALTH_URL`       | `https://www.cloudflare.com/cdn-cgi/trace`   | URL to probe.                                                     |
| `XUI_TUNNEL_HEALTH_INTERVAL`  | `30s`                                        | Interval between probes.                                         |
| `XUI_TUNNEL_HEALTH_TIMEOUT`   | `10s`                                        | Per-probe timeout.                                               |
| `XUI_TUNNEL_HEALTH_FAILURES`  | `3`                                          | Consecutive failures before a restart.                          |
| `XUI_TUNNEL_HEALTH_COOLDOWN`  | `5m`                                         | Minimum delay between restarts.                                 |

## ACME

### `MIKROZIA_CF_API_TOKEN`

The least-privilege Cloudflare API token used for **DNS-01** certificate
issuance and automatic renewal. It is optional: the preferred way is the hidden
interactive prompt (`x-ui` → `14 — TLS Certificates` → `4` or
`x-ui acme cloudflare setup --domain <domain>`), because a value in the RouterOS
Environment is visible in the router configuration. Explicit one-line `--stdin`
is supported for deliberate noninteractive input; generic inherited standard
input is rejected.

The token is never logged, never returned in plaintext by an API, never embedded
in generated configuration, and never written to the immutable image root. It is
stored with mode `0600` on the persistent certificate mount, so it survives an
image replacement and a rollback.

<Callout type="warn">
  A token in the RouterOS Environment is readable by anyone who can read or
  export the router configuration. Prefer the hidden interactive prompt of
  `x-ui acme cloudflare setup --domain <domain>`, restrict the token to the
  single zone (`Zone → DNS → Edit` and `Zone → Zone → Read`), and rotate it
  when somebody else had access to the router.
</Callout>
