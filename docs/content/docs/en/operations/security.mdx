A proxy panel is a high-value target. A few layers of hardening go a long way.

## Panel hardening

- Strong, unique credentials and **two-factor auth** (TOTP).
- A non-default panel port and a long, random web base path.
- TLS on the panel (directly or via a [reverse proxy](/docs/operations/reverse-proxy)).
- The built-in **login limiter** blocks an IP/username after 5 failed attempts
  in 5 minutes (for 15 minutes), and the panel can route its own egress through
  an outbound.

See [First login](/docs/guide/first-login) for the full checklist.

## Client IP logging

The panel records the source IPs it observes for each client through the Xray
online-stats API (see [Clients](/docs/config/clients)). This is observation only:
a RouterOS container cannot install or run Fail2ban, `iptables`, or `nftables`,
and Mikrozia never creates or changes RouterOS firewall rules. Limiting the
number of simultaneous source IPs per client is therefore the RouterOS
administrator's responsibility.

`limitIp` values stored by earlier versions are preserved as-is. They are not
applied by the panel and are not reset, zeroed, or reinterpreted during upgrade,
migration, backup, or restore.

## Network policy

Open only the ports you actually use: RouterOS management, the panel port, the
subscription port, and your inbound ports. Mikrozia has no firewall menu and
ships no `ufw`, `iptables`, or `nftables`; all filter, NAT, port-forwarding,
routing, and access-control policy is configured by the RouterOS administrator.
See [Ports & firewall](/docs/reference/ports-firewall).

<Callout type="warn">
  Keep RouterOS management access working before you apply a restrictive policy.
  Test from a second session so you do not lock yourself out.
</Callout>

## Host kernel boundaries (BBR)

Mikrozia does **not** include a Host Kernel BBR menu or `sysctl` toggle in `x-ui`:

- RouterOS owns the host kernel; a RouterOS Container cannot install kernel modules or change host-kernel TCP congestion algorithms (`net.ipv4.tcp_congestion_control`, `net.core.default_qdisc`).
- Running `sysctl` inside the container cannot create a missing host-kernel congestion algorithm, and RouterOS Queue or Firewall rules cannot substitute for Kernel BBR.
- Userspace congestion control (`bbr`) in **TUIC**, **QUIC**, and **FinalMask** is independent of the host kernel and remains preserved.
- Xray sockopt `tcpcongestion=bbr` is kernel-dependent and remains marked for a separate compatibility audit rather than being presented as RouterOS-verified.

## Keep current

Panel, Xray, sidecars, and Geo data are immutable image content. There is no
in-container software updater. Security fixes arrive in a new versioned image:
pull the new tag from Docker Hub `echodev7/mikrozia`, recreate the container with
the same `/etc/x-ui` and `/root/cert` mounts, and keep the previous image until
the new one is verified. See [Update & uninstall](/docs/guide/update-uninstall).
