Внутри контейнера или через терминал команда `x-ui` является центром управления. Запустите её
без аргументов для интерактивного меню или передайте подкоманду напрямую.

```bash
x-ui
```

## Меню управления `x-ui`

Меню (пункты `0`–`16`) отображает статус панели и Xray в верхней части:

| #     | Пункт                                  | Что делает                                                |
| ----- | -------------------------------------- | --------------------------------------------------------- |
| 1     | Environment-Managed Admin Credentials  | Показать источник учётных данных и команды RouterOS для их задания |
| 2     | Reset Web Base Path                    | Сброс базового веб-пути                                    |
| 3     | Reset Settings                         | Сброс настроек панели (учётные записи сохраняются)         |
| 4     | Change Port                            | Изменить порт панели                                      |
| 5     | View Current Settings                  | Показать имя пользователя, порт, веб-путь, пути к сертификатам |
| 6–7   | Show RouterOS Start / Stop Command     | Показать команды `/container/start` и `/container/stop` для RouterOS |
| 8     | Reload Panel & Restart Xray            | Перезагрузить веб-панель (`SIGHUP`) и перезапустить Xray (`SIGUSR1`) без перезапуска контейнера |
| 9     | Restart Xray Only                      | Отправить `SIGUSR1` для перезапуска только Xray-core внутри контейнера |
| 10    | Check Status                           | Статус панели, Xray и MTProto и команда проверки автозапуска в RouterOS |
| 11    | Logs Management                        | Просмотр отладочного лога панели / команд логов RouterOS   |
| 12–13 | Show RouterOS Enable / Disable Autostart Command | Показать команды `/container/set` в RouterOS для `start-on-boot` и `restart-policy` |
| 14    | TLS Certificates                       | Выпуск, импорт и проверка сертификатов встроенным ACME-клиентом |
| 15    | RouterOS Network Policy Notice         | Памятка по настройке сети и фаервола в RouterOS           |
| 16    | Database Tools                         | Конвертация SQLite `.db` ↔ `.dump` и справка по PostgreSQL |
| 0     | Exit                                   | Выход из скрипта                                          |

Некоторым из этих пунктов посвящены отдельные страницы: [TLS-сертификаты](/docs/config/ssl-certificates)
(пункт 14), [Настройки панели](/docs/config/panel) (TLS), а также [База данных](/docs/reference/database) (PostgreSQL).

## Подкоманды CLI

Для скриптов и быстрых действий `x-ui` принимает подкоманды напрямую:

| Команда                    | Действие                                            |
| -------------------------- | --------------------------------------------------- |
| `x-ui version`             | Показать версию Mikrozia                            |
| `x-ui start` / `stop`      | Показать команды RouterOS (`/container/start` и `/container/stop`); запуск/остановка управляются в RouterOS |
| `x-ui restart`             | Перезагрузить веб-панель и перезапустить Xray внутри контейнера (сам контейнер RouterOS не перезапускается) |
| `x-ui restart-xray`        | Перезапустить только Xray-core внутри работающего контейнера (`SIGUSR1`) |
| `x-ui status`              | Показать статус панели, Xray и MTProto и команду проверки автозапуска RouterOS |
| `x-ui settings`            | Показать текущие настройки                          |
| `x-ui enable` / `disable`  | Показать команды RouterOS `/container/set` для `start-on-boot` и `restart-policy` |
| `x-ui log`                 | Просмотр отладочного лога                           |
| `x-ui migrateDB [file]`    | Конвертация SQLite между .db и .dump                |
| `x-ui acme <command>`     | `status`, `check`, `issue`, `renew`, `cloudflare setup` — сертификаты |

## Обновление

В архитектуре Mikrozia обновление панели выполняется исключительно путём замены контейнера или его образа. Устаревшие скрипты самообновления (`update.sh`), работавшие внутри контейнера, полностью удалены для защиты файловой системы контейнера (RootFS) и стабильности RouterOS.

Для обновления Mikrozia:
1. Загрузите новый тег образа Mikrozia (например, из Docker Hub `echodev7/mikrozia`).
2. Остановите текущий контейнер и пересоздайте его с новым образом, подключив те же постоянные каталоги (`/etc/x-ui` и `/root/cert`).
3. Запустите новый контейнер.

Ваша база данных, пользователи и сертификаты в смонтированных постоянных каталогах полностью сохраняются. Перед обновлением мажорных версий обязательно сделайте [резервную копию](/docs/operations/backup-restore).

### Откат обновления образа

Если новый образ не проходит проверку, оставьте контейнер остановленным, пересоздайте его с предыдущим тегом версии образа и повторно используйте те же монтирования `/etc/x-ui` и `/root/cert`. База данных и сертификаты не входят в образ. Если новый образ уже выполнил миграцию схемы базы данных, восстановите резервную копию базы данных, сделанную до обновления, прежде чем запускать старый образ: старая панель не должна открывать более новую схему. Для отката образа никогда не требуется копировать данные в RootFS образа.

<Callout type="info">
  Контейнер Mikrozia не изменяет собственную файловую систему во время работы. Замена образа гарантирует чистое, неизменяемое и воспроизводимое развёртывание.
</Callout>

Для полного перезапуска контейнера в RouterOS Terminal или WinBox выполните: `/container/restart [find where comment="[Mikrozia:container] Container"]`.

## Удаление

Для удаления Mikrozia в RouterOS:
1. Остановите контейнер: `/container/stop [find where comment="[Mikrozia:container] Container"]`
2. Удалите экземпляр контейнера: `/container/remove [find where comment="[Mikrozia:container] Container"]`

<Callout type="warn">
  Удаление контейнера в RouterOS не удаляет автоматически постоянные смонтированные каталоги (`/etc/x-ui` и `/root/cert`). Удаление базы данных и сертификатов всегда должно быть отдельным, осознанным и явным действием администратора на диске хоста, что полностью исключает случайную потерю данных.
</Callout>
