TLS-сертификат позволяет отдавать **панель** по HTTPS (шифруя вход и трафик API)
и завершать TLS на **входящих подключениях** (VLESS-TLS, Trojan,
Shadowsocks-TLS и т. п.). Mikrozia только **читает** файлы сертификатов, которые
предоставляете вы. Она не запускает ACME-клиент, certbot или другой выпускающий
сертификаты инструмент внутри контейнера.

<Callout type="warn">
  Получение и продление сертификатов выполняет **пользователь**. Mikrozia никогда
  не скачивает и не устанавливает инструменты для сертификатов во время работы и
  никогда не создаёт и не изменяет правила RouterOS для фаервола, NAT или
  проброса портов. Если выбранный способ проверки требует публичный порт,
  настройте доступ самостоятельно в RouterOS.
</Callout>

## Получите сертификат вне контейнера

Используйте процедуру выпуска и продления вашего удостоверяющего центра на
контролируемом вами хосте, затем скопируйте полученные файлы в постоянное
хранилище сертификатов роутера. Не устанавливайте пакеты и не запускайте
установщики сертификатов внутри контейнера Mikrozia.

Сертификат и его закрытый ключ — обычно два файла:

- `fullchain.pem` — сертификат вместе с промежуточной цепочкой.
- `privkey.pem` — закрытый ключ. Держите его в секрете и никогда не помещайте в
  образ, пакет диагностики или журнал.

## Разместите его на постоянном монтировании сертификатов

Создайте отдельный каталог для каждого сертификата в `/root/cert` (путь
контейнера для монтирования сертификатов RouterOS):

```text
/root/cert/vpn.example.com/fullchain.pem
/root/cert/vpn.example.com/privkey.pem
```

Оба файла должны существовать по итоговым путям до настройки панели. Этот
каталог — постоянное монтирование, поэтому сертификаты переживают замену образа
контейнера и откат.

## Укажите файлы в панели

Выберите один из равнозначных способов:

- Запустите `x-ui`, выберите **`14` — TLS Certificate Paths**, затем **`2` — Set
  certificate paths for the panel**.
- Либо выполните команду напрямую:

  ```bash
  x-ui cert -webCert /root/cert/vpn.example.com/fullchain.pem \
    -webCertKey /root/cert/vpn.example.com/privkey.pem
  x-ui restart
  ```

- Либо задайте `webCertFile` и `webKeyFile` в
  [настройках панели](/docs/config/panel#tls).

Панель переключается на HTTPS только когда заданы **оба** пути и оба файла
доступны для чтения. Чтобы очистить их, выполните `x-ui cert -reset`.

## Использование сертификата во входящих подключениях

Когда вы включаете TLS во входящем подключении, укажите те же пути к
сертификату и ключу (или вставьте их содержимое) в настройках TLS этого
подключения. См. [Входящие подключения](/docs/config/inbounds) и
[Транспорты](/docs/config/transports). Входящим подключениям
[REALITY](/docs/config/reality) сертификат **не нужен**: они используют TLS
реального сайта.

## Продление и замена

Продление выполняется вне контейнера по вашему расписанию. Когда центр
сертификации выпускает новый сертификат, перезапишите те же файлы
`fullchain.pem` и `privkey.pem`, чтобы сохранённые в панели пути оставались
актуальными, затем перезагрузите панель:

```bash
x-ui restart
```

`x-ui restart` перезагружает веб-службу и службу подписок панели и перезапускает
Xray внутри работающего контейнера. В контейнере нет демона продления или
задания cron, и никакой сертификат не получается автоматически.

Если вы перенесли сертификат в другой путь, снова обновите настройки панели через
меню `14` или `x-ui cert`.

<Callout type="info">
  Сертификаты истекают. Следите за сроком действия внешними инструментами
  выпуска и заменяйте смонтированные файлы до истечения срока; панель продолжает
  читать файлы по настроенным путям.
</Callout>
