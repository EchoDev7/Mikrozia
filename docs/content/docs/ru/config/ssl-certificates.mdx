TLS-сертификат позволяет отдавать **панель** по HTTPS (шифруя вход и трафик API)
и завершать TLS на **входящих подключениях** (VLESS-TLS, Trojan,
Shadowsocks-TLS и т. п.). Mikrozia содержит закреплённый ACME-клиент внутри образа,
поэтому вы можете выпускать и продлевать сертификаты, не устанавливая ничего на
роутере и не запуская выпускающий сертификаты инструмент на самом RouterOS.

Поддерживаются два способа выпуска:

| Способ                   | Публичный порт 80 | Продление   | Подходит для                                        |
| ------------------------ | ------------------ | ----------- | --------------------------------------------------- |
| **HTTP-01** (вручную)    | Требуется          | Вручную     | Разовые домены, без доступа к API DNS-провайдера.   |
| **Cloudflare DNS-01**    | Не требуется       | Автоматически | Домены, чей DNS обслуживает Cloudflare.             |

<Callout type="warn">
  **Доступность** для проверки домена — ваша ответственность. Mikrozia никогда не
  создаёт, не изменяет, не удаляет, не включает и не выключает правила RouterOS для
  фаервола, NAT, проброса портов, маршрутизации, списков адресов или облачной
  безопасности — ни из панели, ни из меню оболочки, ни из этой документации. Токен
  Cloudflare никогда не попадает в журнал, никогда не возвращается открытым текстом
  через API, никогда не попадает в генерируемые настройки и никогда не записывается
  в неизменяемый корень образа.
</Callout>

## Где хранятся сертификаты

Все данные ACME хранятся на постоянном монтировании сертификатов, поэтому они
переживают замену образа и откат:

```text
/root/cert/vpn.example.com/fullchain.pem   # выпущенный сертификат с цепочкой
/root/cert/vpn.example.com/privkey.pem      # закрытый ключ (0600)
/root/cert/.acme.sh/                         # учётная запись ACME, состояние доменов и продления
```

После успешного выпуска панель и сервер подписок автоматически переключаются на
`/root/cert/<domain>/fullchain.pem` и `/root/cert/<domain>/privkey.pem`. Поля
**Public Key Path** и **Private Key Path** в
[настройках панели](/docs/config/panel#tls) остаются редактируемыми, поэтому
сертификат из другого расположения по-прежнему можно использовать.

## Выпуск сертификата: HTTP-01 (вручную)

Для проверки HTTP-01 нужен TCP-порт 80, доступный из интернета **только на время
выпуска**.

<Steps>

### Сделайте порт 80 доступным для контейнера

Пробросьте публичный TCP/80 на порт 80 контейнера правилом, которым владеете вы.
Панель Mikrozia никогда не пишет это правило за вас. После выпуска сертификата
закройте его — продление ручное, при продлении открывайте снова.

### Проверьте предпосылки

```bash
x-ui acme check --http --domain panel.example.com
```

Вывод показывает встроенный клиент, домашний каталог учётной записи ACME и
локальный DNS-резолвинг. Mikrozia не может проверить публичную доступность
HTTP-01 изнутри контейнера. Оператор RouterOS должен временно сделать TCP-порт
80 доступным из публичного интернета. Команда никогда не считает политику
RouterOS доказательством публичной доступности и не меняет правила роутера.

### Выпустите сертификат

```bash
x-ui acme issue --http --domain panel.example.com
```

или через меню оболочки: запустите `x-ui`, выберите **`14 — TLS Certificates`**, а
затем **`3 — Issue or renew a certificate with HTTP-01 (manual)`**.

При первом использовании клиент регистрирует учётную запись ACME (добавьте
`--email`, чтобы получать уведомления об истечении), проверяет домен и
устанавливает пару на постоянное монтирование. Пути TLS панели и подписок
обновляются только после успешной проверки новой пары: при любой ошибке прежний
сертификат и прежние настройки остаются без изменений.

Для изменённой корректной пары та же транзакция обновляет все четыре пути TLS
панели и подписок и ровно один раз перезагружает панель, слушатель подписок и
Xray. Отдельный перезапуск не нужен. Ошибка перезагрузки отображается, а прежняя
пара и настройки восстанавливаются.

</Steps>

<Callout type="info">
  Сертификаты HTTP-01 **продлеваются вручную**. Панель никогда не планирует
  продление HTTP-01, потому что ему нужен доступ к порту 80, который можете
  обеспечить только вы. Когда срок сертификата приближается, повторите шаги выше с
  открытым портом 80.
</Callout>

## Выпуск сертификата: Cloudflare DNS-01 (автоматически)

Проверка DNS-01 не требует публичного порта. Панель добавляет и удаляет TXT-запись
`_acme-challenge` через API Cloudflare, поэтому трафик проверки не доходит до
роутера.

### Создайте API-токен с минимальными правами

В панели Cloudflare создайте API-токен:

- **Разрешения:** `Zone → DNS → Edit` и `Zone → Zone → Read`.
- **Ресурсы зоны:** `Include → Specific zone → только ваш домен`.

Токен, который может редактировать DNS во всех зонах, не нужен и не должен
использоваться.

### Сохраните токен

Запустите `x-ui`, выберите **`14 — TLS Certificates`**, затем
**`4 — Cloudflare DNS-01 setup and automatic renewal`**. Токен считывается из
скрытого запроса и никогда не выводится на экран.

Тот же скрытый ввод из командной строки:

```bash
x-ui acme cloudflare setup --domain panel.example.com
```

Для намеренного неинтерактивного ввода используйте `MIKROZIA_CF_API_TOKEN` или
передайте одну строку в стандартный ввод только с явным `--stdin`. Обычный
унаследованный стандартный ввод не считается скрытым.

Токен никогда не принимается как аргумент командной строки, поэтому он не попадает
ни в историю оболочки, ни в список процессов. Он хранится с правами `0600` внутри
`/root/cert/.acme.sh/` и передаётся ACME-клиенту только через окружение дочернего
процесса.

### Выпустите сертификат

```bash
x-ui acme issue --dns --domain panel.example.com
```

После успешного выпуска панель оставляет домен в режиме DNS-01, поэтому
запланированное продление распространяется и на него.

### Продление и перезагрузка

Панель проверяет домены DNS-01 дважды в сутки. Встроенный клиент перевыпускает
сертификат только тогда, когда срок его истечения близок, поэтому этот интервал —
частота проверки, а не частота выпуска. Когда установленные файлы действительно
изменились, панель обновляет пути сертификата и перезагружает слушатели; если
ничего не изменилось, перезагрузки не происходит и трафик не прерывается.

### Ротация токена

Создайте новый токен в Cloudflare и снова выполните ту же команду. Новый токен
заменяет предыдущий; после этого старый токен можно отозвать в Cloudflare.

<Callout type="info">
  Токен API Cloudflare можно также передать как переменную окружения контейнера
  `MIKROZIA_CF_API_TOKEN`. Значения RouterOS Environment видны каждому, кто
  может читать или экспортировать конфигурацию RouterOS; это хранилище
  конфигурации, а не секретов. Прочитайте
  [предупреждение о чувствительности](/docs/reference/env-vars#mikrozia-cf-api-token)
  перед использованием.
</Callout>

## Использование уже имеющегося сертификата

Импорт готового сертификата полностью поддерживается и не требует учётной записи
ACME:

- Запустите `x-ui`, выберите **`14 — TLS Certificates`**, затем
  **`2 — Set certificate paths for the panel (manual import)`**.
- Или из командной строки:

  ```bash
  x-ui cert -webCert /root/cert/vpn.example.com/fullchain.pem \
    -webCertKey /root/cert/vpn.example.com/privkey.pem
  x-ui restart
  ```

- Или задайте `webCertFile` и `webKeyFile` в
  [настройках панели](/docs/config/panel#tls).

Панель переключается на HTTPS только тогда, когда **оба** пути заданы и оба файла
читаемы. Чтобы сбросить их, выполните `x-ui cert -reset`.

## Использование сертификата на входящих подключениях

При включении TLS на входящем подключении укажите те же пути сертификата и ключа
(или вставьте их содержимое) в настройках TLS этого входящего подключения. См.
[входящие подключения](/docs/config/inbounds) и
[транспорты](/docs/config/transports). Входящим подключениям
[REALITY](/docs/config/reality) сертификат **не нужен** — они заимствуют TLS
реального сайта.

## Справочник командной строки

```text title="x-ui acme"
x-ui acme status                       # домен, способ проверки, срок действия, режим продления
x-ui acme check --http --domain <d>   # предпосылки HTTP-01 (только чтение)
x-ui acme check --dns  --domain <d>   # предпосылки DNS-01 (только чтение)
x-ui acme issue --http --domain <d>   # выпуск и установка по HTTP-01
x-ui acme issue --dns  --domain <d>   # выпуск и установка по DNS-01
x-ui acme renew --domain <d>          # продление и установка, если файлы изменились
x-ui acme cloudflare setup --domain <d> --stdin
```

`--email <address>` добавляет контакт учётной записи ACME, а `--staging`
использует тестовый каталог ACME (недоверенные сертификаты, которые не расходуют
квоту выпуска — полезно для первого пробного запуска).

## Диагностика

- **Проверка HTTP-01 не проходит.** Порт 80 не был доступен из интернета во время
  выпуска либо на порту 80 уже отвечал другой сервис. Выполните
  `x-ui acme check --http --domain <d>` внутри контейнера.
- **Проверка DNS-01 не проходит.** У токена нет прав `Zone → DNS → Edit` для этой
  зоны либо запись ещё не распространилась. Зона должна быть активна в Cloudflare.
- **Сертификат не стал активным.** Прочитайте ошибку выпуска или продления.
  Ошибка применения/перезагрузки восстанавливает прежнюю пару и все четыре
  прежних пути TLS; устраните причину и повторите команду ACME. Проверьте
  состояние командой `x-ui acme status`.
- **Истечение срока.** Сертификаты истекают. Следите за сроком своими средствами и
  продлевайте заранее; панель продолжает читать файлы по настроенным путям.

## Устарело: поток сертификатов Reverse Proxy на RouterOS

Прежние рекомендации предлагали завершать TLS сертификатом, принадлежащим
RouterOS (или сценарием `certbot` на роутере). Этот поток исключён из текущей
документации: сертификаты выпускает встроенный ACME-клиент и хранит под
`/root/cert`, а Mikrozia никогда не импортирует закрытый ключ RouterOS внутрь
контейнера. Установки, которые всё ещё используют старый поток, продолжают
работать без изменений — обновление образа ничего не удаляет и не переписывает.
Раздача панели через отдельный хост с обратным прокси по-прежнему поддерживается;
см. [Reverse proxy](/docs/operations/reverse-proxy).
