## Между устройствами RouterOS

Переезд на другое устройство RouterOS — это перенос смонтированных данных:

<Steps>

<Step>
### Сделайте резервную копию старого устройства

Остановите контейнер, затем скопируйте содержимое монтирований `/etc/x-ui` и
`/root/cert`. См. [Резервное копирование и восстановление](/docs/operations/backup-restore).
</Step>

<Step>
### Установите тот же тег Mikrozia на новом устройстве

Следуйте [пути установки для RouterOS](/docs/guide/installation) и используйте тот же
тег образа, если только не выполняете осознанное обновление. Создайте те же постоянные
монтирования.
</Step>

<Step>
### Восстановите смонтированные данные

Разместите базу данных и сертификаты на новых постоянных монтированиях до запуска
контейнера. После запуска обновите настройки панели, привязанные к IP или домену.
</Step>

</Steps>

## Между версиями Mikrozia

Замена образа контейнера — единственный поддерживаемый механизм обновления. Панель
мигрирует свою базу данных при запуске. Сначала сделайте
[резервную копию](/docs/operations/backup-restore), пересоздайте контейнер с новым
версионируемым тегом и теми же монтированиями `/etc/x-ui` и `/root/cert`, и сохраняйте
предыдущий образ до проверки нового. Никогда не перезаписывайте RootFS образа изнутри
контейнера.

## С x-ui

Прямой импорт базы данных старой панели x-ui в Mikrozia **не поддерживается** —
схемы различаются. Установите Mikrozia с нуля и заново создайте inbound-соединения и
клиентов, по ходу экспортируя ссылки для подключения из старой панели.

<Callout type="warn">
  Всегда делайте резервную копию перед любой миграцией и не выключайте старый
  сервер, пока не убедитесь в работоспособности нового.
</Callout>
