Обратный прокси позволяет отдавать панель и подписку на аккуратном домене с
автоматическим HTTPS и скрывать реальные порты за портами 80/443. Прокси работает
вне контейнера, обычно на другом хосте. Сама панель тоже может завершать TLS
напрямую с сертификатами, смонтированными на `/root/cert` — см.
[Сертификаты TLS](/docs/config/ssl-certificates).

Прокси должен обращаться к панели по адресу контейнера (`172.16.10.2:2053` в
базовой схеме). Обеспечение этого пути — включая проброс портов или маршрутизацию —
это политика RouterOS, которую настраиваете вы; Mikrozia её не создаёт. См.
[Порты и брандмауэр](/docs/reference/ports-firewall).

## Nginx + сертификат

С Nginx получите сертификат на хосте прокси (вне контейнера Mikrozia) с помощью
`certbot` (или `acme.sh`) и укажите его в блоке server:

```bash title="certbot"
certbot certonly --nginx -d panel.example.com
```

Перезагрузите Nginx после установки сертификата и настройте автоматическое
продление (`certbot renew` по умолчанию запускается по таймеру).

## Caddy

Caddy получает и продлевает сертификаты за вас — направьте Caddyfile на панель,
и всё просто заработает:

```text title="Caddyfile"
panel.example.com {
    reverse_proxy 172.16.10.2:2053 {
        header_up X-Real-IP {remote_host}
    }
}
```

## Советы

- Сохраняйте **базовый веб-путь** панели даже за прокси; это эшелонированная защита.
- Если вы завершаете TLS на прокси, возможно, стоит выставить `XUI_SKIP_HSTS=true` на
  панели — см. [справочник по переменным окружения](/docs/reference/env-vars).
- Проксируйте также сервер [подписки](/docs/config/subscription), чтобы его содержимое
  отдавалось по HTTPS.
