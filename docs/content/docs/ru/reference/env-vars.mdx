Mikrozia читает свою конфигурацию во время выполнения из переменных окружения.
На RouterOS Container задайте их в `/container/envs` и привяжите
`envlist` к контейнеру; для локальной разработки в Docker используйте
`docker-compose.yml` или `docker run -e`. Чтобы применить изменения,
пересоздайте контейнер с теми же постоянными монтированиями (`/etc/x-ui` и `/root/cert`).

## Учётные данные администратора

Окружение контейнера — **авторитетный источник** учётной записи администратора
панели. Никакой фиксированной пары `admin/admin` и никакого сгенерированного
пароля для первого входа нет.

| Переменная              | По умолчанию | Описание                                                              |
| ----------------------- | ------------- | --------------------------------------------------------------------- |
| `MIKROZIA_ADMIN_USERNAME` | —           | Имя администратора. Задаётся вместе с паролем.                        |
| `MIKROZIA_ADMIN_PASSWORD` | —           | Пароль администратора. Задаётся вместе с именем пользователя.          |

При каждом запуске панель приводит сохранённую учётную запись администратора в
соответствие с этими двумя значениями: имя и пароль обновляются, а при смене пароля
аннулируются сессии, выданные со старым паролем. Существующие учётные записи
никогда не удаляются и не сбрасываются молча.

| Ситуация                                                              | Поведение                                                                                         |
| --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Заданы оба значения                                                   | Окружение владеет учётной записью; при каждом запуске она приводится в соответствие.               |
| Задано только одно из двух                                            | Панель не запускается и называет недостающее значение. Ничего не изменяется.                        |
| Не задано ни одного, учётная запись уже существует                   | Сохранённая запись сохраняется без изменений, в журнале отмечается, что ею управляют в другом месте. |
| Не задано ни одного, учётной записи нет                               | Панель не запускается и требует оба значения.                                                       |
| Не задано ни одного, сохранённая запись всё ещё содержит старую пару `admin` / `admin` | Панель не запускается и сохраняет учётную запись.                                 |

Когда учётной записью владеет окружение, вкладка **Безопасность** показывает
уведомление вместо формы смены пароля, а смена пароля из панели отклоняется с
правдивым сообщением: окружение перезапишет его при следующем запуске.

<Callout type="warn">
  **Environment контейнера RouterOS — это хранилище конфигурации, а не секретов.**
  Любое значение в `/container/envs` видно тому, кто может прочитать конфигурацию
  роутера или выгрузить её. Выберите надёжный пароль администратора и защитите
  доступ к самому роутеру и его резервным копиям. Mikrozia никогда не печатает эти
  значения в журнал, никогда не возвращает их через API и никогда не записывает
  их в образ.
</Callout>

## База данных

| Variable                 | Default     | Description                                                          |
| ------------------------ | ----------- | -------------------------------------------------------------------- |
| `XUI_DB_TYPE`            | `sqlite`    | Бэкенд: `sqlite` или `postgres` (также принимаются `postgresql` / `pg`). |
| `XUI_DB_FOLDER`          | `/etc/x-ui` | Папка для файла базы данных SQLite (`x-ui.db`).                     |
| `XUI_DB_DSN`             | —           | Строка подключения PostgreSQL в формате URI (`postgres://`/`postgresql://`) или keyword/value (расширенная настройка при `XUI_DB_TYPE=postgres`). Сертификаты TLS храните в `/root/cert` (рекомендуется `sslmode=verify-full`); `PGPASSWORD` не поддерживается. |
| `XUI_DB_MAX_OPEN_CONNS`  | —           | Максимум открытых соединений в пуле PostgreSQL.                         |
| `XUI_DB_MAX_IDLE_CONNS`  | —           | Максимум простаивающих соединений в пуле PostgreSQL.                         |

Путь к базе данных SQLite по умолчанию — `/etc/x-ui/x-ui.db`. Подробности о
переходе SQLite ↔ PostgreSQL см. в разделе
[База данных](/docs/reference/database).

## Панель

| Variable                 | Default | Description                                                              |
| ------------------------ | ------- | ------------------------------------------------------------------------ |
| `XUI_PORT`               | —       | Переопределение порта панели (1–65535). Имеет приоритет над сохранённой настройкой. |
| `XUI_INIT_WEB_BASE_PATH` | `/`     | Начальный базовый веб-путь при **первом** запуске (например, `/panel`).               |
| `XUI_SKIP_HSTS`          | `false` | Не отправлять заголовок HSTS — установите `true`, когда TLS терминируется обратным прокси. |

## Шифрование токенов узлов

API-токены узлов — и сохранённый токен PIA — по умолчанию хранятся в открытом
виде. Шифрование при хранении включается явно и отказывает безопасно: при любом
режиме, кроме `off`, панель не запустится, если не сможет загрузить ключ.

| Variable                  | Default                         | Description                                                                                                                                                            |
| ------------------------- | ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `NODE_TOKEN_ENCRYPTION`   | `off`                           | `off`, `migration` (чтение принимает открытый текст или шифротекст, запись всегда шифрует) или `required` (запись та же, но без ключа запуск не удастся). Префикса `XUI_` здесь нет. |
| `XUI_NODE_TOKEN_KEY_FILE` | `/etc/x-ui/node_token_key.json` | JSON-связка ключей с правами `0600` или строже. Загружается первой.                                               |
| `XUI_NODE_TOKEN_KEY`      | —                               | Один 32-байтный ключ в base64, читается только при неудачной загрузке файла ключей. Его идентификатор фиксирован (`env`), поэтому ротация невозможна.                   |

Файл ключей задаёт активный ключ и все прежние ключи, ещё нужные для расшифровки:

```json
{ "active": "k1", "keys": { "k1": "<base64 32-byte key>" } }
```

Сгенерируйте ключ командой `openssl rand -base64 32`; ключи никогда не
принимаются в аргументах командной строки. После включения режима перешифруйте
строки, уже находящиеся в базе, активным ключом:

```bash
x-ui encrypt-tokens
```

Команда обрабатывает строки узлов; токен PIA перешифровывается при следующем
чтении. Для ротации добавьте новый ключ в `keys`, укажите его в `active`,
сохраните старый ключ для расшифровки и снова выполните `x-ui encrypt-tokens`.

## Память и профилирование

Панель удерживает потребление памяти низким за счёт `GOGC` и периодических
освобождений. Это продвинутые параметры — оставьте их незаданными, если только
вы не настраиваете хост с ограниченными ресурсами.

| Variable                      | Default | Description                                                       |
| ----------------------------- | ------- | ----------------------------------------------------------------- |
| `XUI_GOGC`                    | —       | Целевой процент сборщика мусора Go; ниже = меньше RAM, чуть больше нагрузка на CPU.     |
| `XUI_MEMORY_RELEASE_INTERVAL` | —       | Минуты между вызовами `FreeOSMemory`; `0` отключает.               |
| `XUI_MEMORY_LIMIT`            | —       | Мягкий лимит памяти Go в **MiB**.                                  |
| `GOMEMLIMIT`                  | —       | Мягкий лимит в синтаксисе Go (например, `400MiB`); имеет приоритет над предыдущим.|
| `XUI_PPROF`                   | `false` | Открыть профилирование pprof на `127.0.0.1:6060`.                       |

## Монитор работоспособности туннеля

Опциональный сторож: он опрашивает URL (опционально **через** локальный входящий
Xray) и перезапускает Xray после нескольких неудачных попыток подряд. Перезапуск
обрывает все подключённые клиенты, поэтому включайте его осознанно.

| Variable                      | Default                                      | Description                                                       |
| ----------------------------- | -------------------------------------------- | ----------------------------------------------------------------- |
| `XUI_TUNNEL_HEALTH_MONITOR`   | `false`                                      | Включить монитор.                                               |
| `XUI_TUNNEL_HEALTH_PROXY`     | —                                            | Прокси, через который отправляется проба, например `socks5://127.0.0.1:1080`. Пусто = проверяется только доступность хоста. |
| `XUI_TUNNEL_HEALTH_URL`       | `https://www.cloudflare.com/cdn-cgi/trace`   | URL для опроса.                                                     |
| `XUI_TUNNEL_HEALTH_INTERVAL`  | `30s`                                        | Интервал между пробами.                                         |
| `XUI_TUNNEL_HEALTH_TIMEOUT`   | `10s`                                        | Тайм-аут одной пробы.                                            |
| `XUI_TUNNEL_HEALTH_FAILURES`  | `3`                                          | Количество неудач подряд до перезапуска.                          |
| `XUI_TUNNEL_HEALTH_COOLDOWN`  | `5m`                                         | Минимальная задержка между перезапусками.                                 |

## ACME

### `MIKROZIA_CF_API_TOKEN`

API-токен Cloudflare с минимальными правами, который используется для выпуска
сертификатов и автоматического продления по способу **DNS-01**. Переменная
необязательна: токен можно сохранить интерактивно (`x-ui` → `14 — TLS
Certificates` → `4` или `x-ui acme cloudflare setup --domain <domain>`) —
это предпочтительный способ, потому что значение в RouterOS Environment видно в
конфигурации роутера. Явный однострочный `--stdin` поддерживается только для
намеренного неинтерактивного ввода; обычный унаследованный stdin отклоняется.

Токен никогда не попадает в журнал, никогда не возвращается открытым текстом через
API, никогда не попадает в генерируемые настройки и никогда не записывается в
неизменяемый корень образа. Он хранится с правами `0600` на постоянном
монтировании сертификатов, поэтому переживает замену образа и откат.

<Callout type="warn">
  Токен в RouterOS Environment доступен тому, кто может прочитать или
  экспортировать конфигурацию роутера. Предпочтите скрытый интерактивный ввод
  `x-ui acme cloudflare setup --domain <domain>`,
  ограничьте токен одной зоной (`Zone → DNS → Edit` и `Zone → Zone → Read`) и
  выполните ротацию, если кто-то ещё имел доступ к роутеру.
</Callout>
